# SV-01 R4 플레이어 적용

승인된 R4 외형·재질·조명을 유지한 본체 리소스입니다. 2026-09-07 후속 요청으로 과도한 화면 회전을 완화하고, 게임용 21장을 축소한 무손실 WebP로 교체했습니다.

## 현재 실행 자산

- 실행용: `webp/`의 **21장, 192×192 RGBA, 무손실 WebP**. `manifest.json` version 2가 파일 순서·해시·피벗을 정의합니다.
- 원본: 이 폴더의 기존 **256×256 PNG 21장**과 `source-manifest.json`을 그대로 보존합니다. `preview_sheet.png`, `alpha_check.png`는 기존 PNG 확인 자료입니다.
- 순서: **00–09 하강 74.0→7.4° / 10 중립 0° / 11–20 상승 7.4→74.0°**, 간격 7.4°. 90° 포즈는 없습니다.
- 중심: WebP **(96,96)**, 정규화 **(0.5,0.5)**. 원본 (128,128)에서 같은 비율로 축소했고 크롭·프레임별 중앙 재정렬은 하지 않았습니다.
- 실제 게임 표시 크기는 기존 **106×106 게임 단위**입니다. 프레임별 투영 외곽과 투명 영역 변화는 뱅크 동작의 일부입니다.

## 뱅크와 화면 회전

기존 `player.angle`은 이동에 따라 보간되는 신호로 계속 사용합니다. 신호를 줄이면 21단계 뱅크 자체가 사라지므로, 이미지 선택과 화면 회전을 분리했습니다.

```js
const bankFrame = Math.round(10 - clamp(p.angle / .48,-1,1) * 10);
c.rotate(playerHeading(p));
c.drawImage(this.playerFrames[bankFrame],-53,-53,106,106);
```

- **뱅크:** 하강 00 / 중립 10 / 상승 20, 기존 21장과 이동 보간 그대로.
- **화면 회전:** 기존 `p.angle * 2.4`의 최대 **±66.00°**에서, 탄의 전방 진행 축을 기준으로 **±6°**로 완화합니다. 카메라 기울기는 기체와 탄에 공통으로 적용됩니다.
- `src/game.js`의 `playerHeading()`을 본체·총구 위치·추진 궤적 연결점·엔진 광원 방향이 함께 사용합니다. 회전을 줄여도 총구와 궤적이 예전 큰 각도의 위치에 남지 않습니다.
- 총구의 기존 로컬 오프셋 (30,−4)은 유지합니다. 탄의 속도·진행 방향·패턴·발사 간격은 바꾸지 않습니다.

## 크기 선택과 절감

| 21장 합계 | 이전 PNG | 현재 WebP | 감소 |
|---|---:|---:|---:|
| 전송 파일 크기 | 511,178B | 251,024B | 50.89% |
| 디코딩 RGBA 계산값 | 5,505,024B | 3,096,576B | 43.75% |

128/160/192px 후보를 실제 표시 크기 106/159/212px에서 비교했습니다. 192px는 작은 후보보다 날개·패널·노즐 경계를 잘 보존하면서 용량을 절반가량 줄입니다. 검정·흰색·하늘 배경의 투명 가장자리도 비교했습니다. 과도하게 확대되는 화면·모든 GPU의 선명도를 보장한 것은 아닙니다.

축소는 선곱 알파 Lanczos를 사용하고, 그 결과를 **무손실 WebP**로 인코딩합니다. WebP 디코드가 축소 RGBA와 바이트 단위로 일치함을 검사합니다. 원래 256 PNG를 축소하며 줄어드는 정보까지 손실이 없다는 뜻은 아닙니다.

`tools/optimize-player-sprites.py`로 재생성할 수 있습니다. Python/Pillow(WebP 지원)는 자산 재제작 때만 필요하며 게임 실행 의존성이 아닙니다. 입력은 보존된 `source-manifest.json`이며 원본 PNG의 SHA를 검사합니다. 의도적으로 다른 크기로 다시 생성하면 런타임 매니페스트의 치수·피벗·해시도 맞춰야 합니다.

## 실행과 검증

`Renderer.load()`와 `tools/build-site.mjs`는 현재 매니페스트의 **WebP만** 읽고 포함합니다. PNG 원본·원본 매니페스트·비교 이미지는 기체 실행 자산에 포함하지 않습니다. 기존 드론에는 별도 `assets/art/player.png`를 계속 사용합니다.

```powershell
npm test
npm run check
npm run build:site
npm start
```

이전 PNG가 남은 `dist/`는 빌드의 불필요 파일 검사가 거부합니다. 필요한 기존 빌드는 별도로 보관하고 빈 `dist/`에 다시 빌드하세요. 원본 `assets/`의 PNG를 삭제하는 작업이 아닙니다.

`http://127.0.0.1:5173/`에서 새로고침 후 START → 상승/하강 → 입력 해제로 확인합니다. 자산 규격·순서·해시·원본 보존, 부드러운 화면 회전/총구·카메라 정렬과 기존 상태 보존을 테스트합니다. 영상은 새로 녹화하지 않습니다.

이동 범위·피격 반경 1.85·무기 성능·드롭·난이도·음악·지상 디자인은 유지합니다. 새 아이템, 드론 외형 교체, 추가 외형 수정은 이번 범위가 아닙니다. 공개 배포와 Git 커밋/푸시는 별도 요청에서 수행합니다.
