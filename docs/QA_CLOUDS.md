## 정적 검증

- `node --check src/volume-environment.js`: 통과.
- 수정 전 사본과 최종 소스에서 `density()`, 베이크 문자열, `setLights()`, 전경 흡수 계수를 제외한 코드는 동일하다. `setLights()`의 카메라 오프셋 반영은 별도 카메라 작업의 변경이다. 후보 채택 직전에는 1차 시안과 후보의 density/전경 흡수 외 코드가 동일함을 확인했다.
- `density()` 안 텍스처 호출 수: 수정 전 11, 수정 후 11.
- 베이크 빛 샘플: 12회 유지. 프레임 ray march: 최대 128회 유지.
- 베이크 캐시: 512 × 64 × 512 RGBA8, 64 MiB 유지. 소음 텍스처: 128³ RGBA8 유지.
- 주기 1024, X→Z shear 0.137 및 정수 XYZ 주파수 유지. 주기 경계 연속성의 수학적 전제는 유지하지만 실제 seam은 캡처로 확인해야 한다.
- 카메라 높이 계산 28 + altitude × 190, altitude 입력, 투영/역행렬, `lightWorld()` 계산 및 베이크 sun shear 변환은 유지한다. `setLights()`에서 `lightWorld()`에 전달하는 플레이어·섬광의 X/Y 좌표에는 `renderer.cameraOffset`을 반영한다.
- 지상 렌더링, 지상 자산, 음악, 전경 분할을 유지했다. 구름 근경 흡수 계수는 채택 후보에서 0.075→0.045로 낮췄다.

샘플 수/할당량에 관한 위 항목은 정적 확인이며 FPS 측정 결과가 아니다. 별도로 수행한 배경 WebGL GPU 측정은 아래에 기록했다. 밀도 변화에 따른 조기 종료 횟수 자체는 측정하지 않았다.

## 남은 형태·흐림의 원인과 채택 후보

아래는 소스의 구조와 정지 화면에 근거한 진단이며, 원인을 분리한 GPU 실험이나 성능 측정 결과가 아니다.

- 1차 시안의 큰 Worley 셀 크기는 X/Y/Z 약 64 / 21.3 / 42.7 world unit이다. 가로에 비해 수직 형태가 낮도록 변환되어 있다. 저주파 coverage는 큰 구역을 만들지만 자체적으로 높이 솟는 덩어리를 만들지는 않는다.
- `thickness`가 `113 - floorHeight`로 제한되면 다른 봉우리가 같은 높이 상한에 도달할 수 있다. 실제 몇 퍼센트의 영역이 clamp되는지는 측정하지 않았으므로 주원인으로 단정하지 않는다.
- `altitude = 0.30`에서 카메라 높이는 85로, 58~116 구름층 안이다. 근경 43 world unit을 평균 밀도 0.25로 통과한다고 단순화하면 흡수 계수 0.075의 불투명도는 `1 - exp(-0.25 × 43 × 0.075) ≈ 55%`다. 평균 밀도 0.5이면 약 80%다. 이 수치는 실제 픽셀 측정이 아니라 넓은 근경 밀도 누적이 가림을 만들 수 있음을 보여주는 계산이다.
- 구름 화면은 가로·세로 절반 해상도에서 확대되지만, 이것만으로 수백 픽셀 규모의 흐림을 설명하기는 어렵다. 캐시의 X/Z 간격 2 world unit이 아주 가까운 거리에서 크게 투영되고 부드러운 밀도 경계가 누적되는 영향도 유력하다. 해상도를 올리는 변경은 하지 않았다.

1차 적용본을 복사한 `Feedback/candidate-volume-environment.js` 한 개에서 `density()`와 전경 흡수만 변경했다. 같은 조건의 캡처를 직접 비교한 뒤 이 후보를 최종 소스에 적용했다. 추가 타일·변형이나 새 구름 시스템이 아니다.

| 후보 항목 | 1차 시안 | 채택 후보 |
|---|---|---|
| 큰 Worley 주파수 / 셀 크기 XYZ | 2/6/3, 약 64/21.3/42.7 | 4/6/4, 약 32/21.3/32 |
| 높이 구성 | 두께 합산 후 hard min | `1 - (1-weather) × (1-crest)`로 23~상한 사이 보간 |
| 작은 요철 최대 혼합 | 0.42 | 0.28 |
| 리본 최대 혼합 | 0.25 | 0.15 |
| 높이 profile 중심 / 감쇠 계수 | 0.36 / 0.60 | 0.46 / 0.48 |
| 경계 밀도 smoothstep | 0.015~0.17 | 0.03~0.15 |
| 전경 흡수 | 0.075 | 0.045 |

큰 coverage 마스크와 기존 빛·색은 유지한다. 후보는 더 원형에 가까운 수직 굴곡들이 큰 구역 안에서 이어지게 하고, 넓고 희박한 근경 누적을 낮추려는 한 조합이다. 전경을 없애지는 않는다. 위의 단순 43-unit 계산에서 후보 불투명도는 평균 밀도 0.25일 때 약 38%, 0.5일 때 약 62%다.

후보와 최종 적용본에 대해 각각 `node --check`를 통과했다. 1차 시안과 비교하여 density/전경 흡수 외 코드는 동일하며, density 텍스처 호출 11회, 샘플 상한, 캐시 크기, 구름 높이 58~116, 카메라와 광원 좌표를 유지함을 확인했다.

## 후보 캡처와 채택 판단

`Feedback/QA/cloud-candidate.png`, `cloud-candidate-side.png`, `cloud-candidate-rim.png`를 직접 열어 1차 시안과 비교했다. 첫 두 장은 각각 같은 위치의 `altitude = 0.48`, `0.30` 조건이다. 1차 캡처와 후보 캡처는 픽셀 해상도가 다르므로 형태·명암·공간 구성을 비교했으며 픽셀 단위 일치 비교로 취급하지 않는다.

- **0.48 대표 장면:** 1차 시안의 얇은 돌출부와 파편이 차지하던 중경에서 둥근 굴곡들이 더 큰 연결 덩어리를 이룬다. 근경도 높이가 있는 몸체와 깊은 옆면이 분명해졌다. 중앙의 빈 구역을 완전히 메우지 않으면서 구름 본체의 양감이 개선되어 이 후보를 채택했다.
- **0.30 구름 내부:** 숲은 1차 시안보다 대비가 좋아졌지만, 더 큰 구름 본체가 하늘을 많이 가린다. 낮춘 전경 흡수만으로 전체 가림이 해결된 것은 아니다. 넓고 흐린 내부와 경계는 여전히 남는다.
- **구름 가장자리:** 중경의 굴곡과 음영은 읽히지만 근경에는 커다란 흐린 덩어리가 겹친다. 중경과 근경의 선명도 차이가 크고, 참고 프레임의 정교한 수직 봉우리·경계 질감 수준에는 도달하지 않았다.

샘플 수와 512×64×512 캐시를 유지하는 이번 변경은 형태 분포와 광학 누적을 조정한 것이다. 가까운 2-world-unit X/Z 캐시 간격의 투영, 부드러운 밀도 보간, 최대 128회 ray march, 절반 해상도 구름 버퍼는 그대로 남는다. 따라서 내부·극근경의 흐림까지 제거했다고 주장하지 않는다. 캐시나 샘플을 늘리는 것이 확실한 해결책이라는 검증도 하지 않았다. 새 자산·해상도·별도 레이어를 추가하지 않는 한계 안에서 한 대표 후보를 선택했으며, 다른 후보는 추가하지 않았다.

## 후속 이동 캡처와 전투 표시 검증

검증 산출물은 `Feedback/QA/flight-25s.webm`, `flight-capture-log.json`, `flight-motion-01.png`~`flight-motion-05.png`다. 검증 담당이 `ffprobe`로 확인한 영상 길이는 24.989138초, 해상도는 1280×720, 디코딩 프레임 수는 511이다. JSON 로그는 draw 호출 537회, wall time 25.0356초, simulation time 25.0077초를 기록한다. draw 호출 수와 녹화 프레임 수는 같지 않다.

캡처 환경의 네이티브 `requestAnimationFrame`이 25초에 25프레임으로 제한되어, 녹화에만 30Hz `setTimeout` 스케줄을 사용했다. 각 캡처 tick에서 실제 `updateGame(dt)`와 `renderer.draw`를 실행하고 `captureStream`의 `requestFrame()`을 요청했다. 기록은 고정 시드·무적 상태의 초기 25초 상하 비행과 발사이며 오디오는 포함하지 않는다. 30Hz는 요청 스케줄이며 실제 30 FPS를 달성했다는 뜻이 아니다. 이 영상의 프레임 수나 간격을 정상 게임 루프의 FPS로 사용하지 않는다.

추출 프레임 02와 04는 검증 담당과 구름 담당이 직접 열어 확인했다. 02에서는 구름 내부의 안개와 발사 효과 위에 분홍 적탄 윤곽이 보이고, 04에서는 넓은 푸른 하늘과 화면 아래의 구름이 분리되어 고도 변화에 따른 구성 차이가 보인다. 이는 선택된 정지 프레임의 확인이다. 영상 전체의 모든 seam/popping 부재나 사람이 읽고 회피하기 편하다는 검증으로 확대하지 않는다.

`Feedback/QA/cloud-combat-readability.png`는 가장 밝은 구름 안의 충돌·표시 fixture다. 검증 담당이 실제 충돌 코드를 실행해 HP 13 감소를 확인했고, 전경 구름을 그린 뒤 적탄과 피격 링을 표시하는 동작을 확인했다. 이미지에서도 밝은 구름 위의 분홍 적탄, 어두운 테두리, 피격 링이 구분된다. 자연 발생 전투에서 사람의 회피 성능이나 피격 원인 분포를 측정한 결과는 아니다.

## 배경 WebGL GPU 측정

근거 파일은 `Feedback/QA/gpu-webgl-paired.json`이다. RTX 4060, ANGLE D3D11 환경에서 `EXT_disjoint_timer_query_webgl2`로 원본과 최종 적용본을 같은 조건에서 번갈아 측정했다. 고도별 warmup 4회 후 각각 20개 샘플을 수집했다. Canvas `drawImage`는 no-op 처리하여 캔버스 복사를 제외하고 WebGL 지형·구름 패스만 측정했다.

| altitude | 원본 GPU 중앙값 (ms) | 최종 GPU 중앙값 (ms) | 최종 p95 (ms) |
|---|---:|---:|---:|
| 0.00 | 3.157 | 2.415 | 9.557 |
| 0.30 | 3.450 | 3.169 | 10.445 |
| 0.48 | 2.478 | 3.297 | 10.295 |
| 0.95 | 1.671 | 1.829 | 8.934 |

결과는 고도에 따라 달라진다. 대표 고도 0.48의 중앙값은 약 0.819ms 증가했으므로 샘플 수가 같다는 이유로 비용이 같거나 전반적으로 빨라졌다고 주장하지 않는다. 소수 샘플의 배경 GPU 구간 측정이며 CPU 게임 로직, Canvas 복사/동기화, 전체 합성, 입력, 녹화 비용을 포함한 프레임 시간이나 실전 FPS가 아니다.

초기 `Feedback/QA/gpu-before-after.json`은 전체 renderer 구간에서 Canvas 동기화가 포함된 측정이므로 순수 WebGL GPU 비용이나 실제 FPS의 근거로 사용하지 않는다. 후속 검증 뒤 현재 소스와 후보의 SHA-256이 위 최종 해시와 동일함을 재확인했다.

## 검증 범위와 남은 항목

페이지를 새로 로드해 볼륨을 재베이크한 뒤 수정 전후 동일 상태로 캡처한다.

1. `distance = 0`, `altitude = 0.48`: 원본→1차→채택 후보 정지 화면 비교 완료. 후보의 양감 개선과 남은 근경 흐림을 기록했다.
2. `distance = 1024 / 76`, `altitude = 0.48`: 정지 화면 확인 완료. 이동 중 경계 이음새와 인접 구간의 구성 변화는 추가 확인 필요.
3. `altitude = 0.30` 부근: 1차와 채택 후보 비교 완료. 내부의 흐림과 큰 본체의 가림은 미해결 항목이다.
4. 20~30초 이동 산출물: 약 25초의 고정 시드 비행·발사 영상과 추출 프레임 확보. 선택 프레임의 고도별 구성과 적탄 윤곽을 확인했다. 모든 이동 구간의 seam/popping과 정상 rAF 실전 FPS 검증은 남는다.
5. 가장 밝은 구름의 전투 표시: 실제 충돌 fixture의 HP 13 감소와 post-front 적탄·피격 링 확인 완료. 사람이 하는 회피 플레이는 검증하지 않았다.

직사각형 경계, 후광, 절벽 형태, 균일한 흐림, 과한 늘어짐은 대표 장면 승인 시 확인할 항목이다. 참고 영상과 정확히 일치한다는 주장은 하지 않는다. 원문에 따라 대표 구름 장면의 품질 승인 뒤에 반복 타일·변형을 확장한다. 이번 기록은 청음이나 실제 태블릿 기기 검증 결과를 포함하지 않는다.
