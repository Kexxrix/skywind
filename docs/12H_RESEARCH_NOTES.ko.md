## 실제 비교에서 바꾼 판단

고정 baseline과 prototype-01에 같은 입력 정책을 적용했다. 첫 후보는 피해가 몸통 돌진에 집중되었고 목표 시간 창에 느린/빠른 탄의 실제 근접 도착이 겹치지 않았다. 생존이 짧아졌다는 사실만으로 사용자의 약3분 판단 압박 목표를 달성했다고 판정하지 않았다. 이 입력 모델은 현재 화면 좌표와 두 관측 사이 속도를 이용하며 예고의 의미·곡선의 미래·사람의 인식과 재미를 대신하지 않는다.

우선 원인을 탄막 개수보다 연결과 발사 기회에서 찾았다. 발사 적이 기본 중앙 사격선에서 먼저 처치되면 긴 공간 제어 시퀀스의 후속 조준탄이 나오지 않는다. 서로 다른 가족 분류가 예약 상한을 먼저 차지하면 다른 역할은 존재해도 실제 공격하지 못한다. 카메라가 회전하는데 적의 정지 위치를 world X로만 고정하면 화면상의 발사 거리도 의도와 달라진다.

다음 후보는 일반 적의 화면 기준 정지 열과 최초 공격 지연을 명시해, 원거리 공간 제어 발사 적·별도 빠른 조준 사수·몸통 역할의 순서를 실제로 연결한다. `holdScreenX`, `initialAttackDelay`는 레벨 데이터이고 이동/발사는 `src/game.js`가 소비한다. 동일한 공간 제어 가족으로 묶는 분류에는 실제 행동 근거가 필요하며, 가족 이름을 합친 결과만으로 복합 위협의 공정함을 통과시키지 않는다.

## 이번 반복의 합격 관문

1. 같은 controller·seed·완료된 시간 창에서 실제 느린 탄과 빠른 탄의 근접 도착, 공격 시작 전 처치, 피해/회복 장부를 비교한다. 사망해 짧아진 시간 창은 비교 불가로 남긴다.
2. 확정 조준은 예고 중 표적을 잠그고 발사 후 추적하지 않는다. 과거 표적까지의 거리만으로 최소 비행시간을 계산하지 않고 현재 플레이어가 정상 속도로 도달할 수 있는 영역도 검사한다. 거절만 늘린 결과는 실제 안전한 발사를 확인하기 전 통과로 표시하지 않는다.
3. 몸통 돌진에도 공격 계열·공격원 상한을 적용한다. 보이는 예고와 실제 고정 경로를 유지하며 무조건 사망시키는 압박을 목표로 삼지 않는다.
4. 실제 장갑 조각은 노출 코어로 향하는 경로 위에서도 탄을 막는다. 몸체가 바뀌는 substep에서는 시간별 실제 프레임의 compound hull을 판정하고 빈 공간을 합쳐 메우지 않는다.
5. 자동 검사·실제 음소거 브라우저 관측·독립 QA·사용자 체감·직접 청음을 각각 기록한다. 새 아트가 로컬로 전달되지 않은 상태를 시제품 외형의 완성으로 보고하지 않는다.

## 발사 주체·수명·예약의 추가 근거

부모가 제공한 스케줄 연구를 받아 다음 원본3개를 직접 읽었다. [Kenta Cho의 BulletML 공식 참조](https://www.asahi-net.or.jp/~cs8k-cyu/bulletml/bulletml_ref.html)는 bullet의 action에 wait/fire/vanish와 방향·속도 변화를 정의한다. 발사 적과 탄의 행동 시계를 분리할 수 있다는 참고이며 SkyWind의 예산·소유권 규칙을 제공하지 않는다.

[Taisei 개발자의 task DSL](https://raw.githubusercontent.com/taisei-project/taisei/master/src/coroutine/taskdsl.h)은 parent 종료가 subtask를 종료하는 수명 관계와 지연 호출의 인수를 다룬다. [Taisei Stage3 실제 소스](https://raw.githubusercontent.com/taisei-project/taisei/master/src/stages/stage3/timeline.c)는 적의 발사 loop와 projectile에 연결된 별도 행동, loop 전 조준과 loop 안 조준을 구분한다. 다른 엔진의 구조를 그대로 가져오지 않고 발사 주체의 사망이 어떤 미래 공격을 취소하는지 명시해야 한다는 근거로 사용한다. 코드·자산을 복사하지 않았다.

이번 작은 연결에서는 새 projectile-owned 공격 노드 대신 기존에 보이는 field 적과 독립 사수를 선택했다. 유한 seed continuation은 추가 소유권·삭제·예고·후손 예산을 연결해야 하므로 이미 있는 두 역할로 원인을 먼저 해결한다. 느린 field에서 지연 aim을 제거하고 독립 rail/snapshot은 자신의 포구·잠금·수명을 유지한다. 발사된 기존 탄은 원래 유한 수명과 전투 정리를 따르며 죽은 적의 포구가 다시 쏘지 않는다.

구성의 동시 예약은 위 원본의 사실이 아니라 이번 프로젝트의 기술 선택이다. 같은 wave의 핵심 역할을 전부 생성할 자리가 있을 때만 만들고, 실제 포구·가시성을 확인한 뒤 전체 가족/공격자/aim/탄 예산을 한꺼번에 예약한다. 아직 시작하지 않은 사수의 예약은 charge나 lock가 아니다. 각 역할은 한 시퀀스만 발사하고, 남은 normalTime 기한에 전부 들어가지 않으면 예고 전에 거절한다. 처치·가시성 상실·마감·전투 정리는 미사용 예약을 해제한다. 이미 낸 탄과 독립 사수의 미래 공격은 다른 소유권으로 남긴다.

한 단면의 거리/명목 속도 계산은 움직이는 플레이어 영역 전체의 동시 도착을 보장하지 않는다. 동일한 source와 두 수평 속도라면 단면 차이 dx가 상대 도착에 주는 차이는 dx×(1/vSlow−1/vFast)다. 곡선·가속·경사진 직사는 실제 vx/궤적을 따로 읽는다. 새로운 copied scratch에서는 고정·단순 이동·300/500ms 반응·기존 v2를 비교했고 반응 지연의 결과도 단조롭지 않았다. v2의 확정 피해나 한 핵 근접 지표에 맞추지 않으며 움직여 피한 결과도 별도 증거로 남긴다.

actual 연결은 `.work/12h-build/evidence/experiments/level-schedule-03/PRODUCTION_ADDENDUM.ko.txt`, 예약·처치·마감 경계는 `tests/12h-phrase.test.js`와 `.work/12h-build/evidence/phrase-budget-prototype03`에 연결한다. Stage3 직행과 실제0초 시작120~180초 진행은 서로 다른 검사다. 회복량이나 몸통 피해를 탄 압박의 대체 합격 근거로 쓰지 않는다.
