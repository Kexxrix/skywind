## 이 문서의 검증 범위

참조 영상의 프레임과 공개 웹페이지의 텍스트 UI는 확인했다. 그러나 검토 환경에서 조작용 브라우저의 사이트 접속이 `net::ERR_BLOCKED_BY_ADMINISTRATOR`로 차단됐다. 현재 배포본의 실제 플레이, 렌더링 화면, 청음, 소스 및 수치 검증은 완료하지 못했다. 본 문서의 현재 문제는 사용자의 증상 보고이고, 수정 수치와 구현 방식은 검증할 설계 제안이다. 특정 프레임워크, 원인 코드, 실제 무기 목록을 확인한 것으로 취급하지 않는다.

첨부한 JPG는 모두 **참조 영상에서 추출한 장면**이다. 현 배포본의 스크린샷이나 수정 결과물이 아니다. 위쪽 게임 화면만 잘랐으며, 그림을 새로 생성하거나 보정하지 않았다.

## 작업 목표와 유지 조건

목표는 공중을 넓게 비행하며 탄막을 피하는 상쾌함, 입체감 있는 대규모 구름, 서서히 올라가는 생존 난이도, 명확한 무기 상태와 타격 피드백이다.

- 사용자가 만족한 지상 표현과 음악의 구성·음원을 유지한다.
- 기존 게임 엔진과 프로젝트 구조를 유지한다. 전체 재작성, 렌더러 교체, 불필요한 대형 의존성 추가를 하지 않는다.
- 실제 구현을 조사한 뒤 최소 수정한다. 아래의 예시 무기명·이벤트명은 기존 코드의 이름이라고 가정하지 않는다.
- 외부 플러그인 사용, 신규 이미지 생성이 필요한 경우 먼저 사용자의 승인을 받는다.
- 승인 전 제목을 바꾸지 않는다. 제목 후보와 게임 튜닝을 별도 작업으로 취급한다.

## 0. 수정 전 조사와 비교 기준 고정

실제 파일과 심볼을 찾아 다음을 기록한다: 이동 경계, 월드/화면 좌표 변환, 카메라 추적, 배경 레이어, 구름 생성·로드, 경과 시간, 난이도 계산, 적 생성과 발사 스케줄, 무기 목록, 획득/갱신/만료, 탄환 생성·충돌, 오디오 재생 진입점.

현재 값을 먼저 출력한다. 특히 아래 항목은 추정하지 말고 코드에서 확인한다.

- 기준 고도, `yMin/yMax`, 플레이어 속도와 히트박스, 실제 보이는 게임 영역.
- 0/30/60/120/180/300초의 난이도, 생성 간격, 적 상한, 동시 발사자 상한, 탄속, 발사 주기, 발당 탄수, 적 체력.
- 모든 무기의 실제 동작, 지속 시간, 중복 획득·교체·중첩 규칙.
- 사운드가 호출되는 실제 이벤트, 로딩·캐시, 동시 발음 관리.

밀리초/초 혼동, 프레임 수에 의존한 시간 증가, 재시작 시 중복 타이머/리스너, 일시정지 중 시간 증가를 점검한다. 이것들이 현재 버그라고 가정하지는 않는다.

비교용 고정 시드를 만들거나 기존 결정적 재현 기능을 사용한다. 스폰 결과를 재현할 수 있게 하되, 확인되지 않은 버그를 고치기 위해 시스템 전체를 교체하지 않는다.

## 1. 상하 이동 범위: 기준 고도에서 양방향 거리 각각 1.5배

움직이는 구름 스프라이트의 중심을 매 프레임 추적해 경계를 정하지 않는다. 기존 비행 공간의 안정된 기준 고도 `centerY`를 사용한다.

```text
oldUpRange   = centerY - oldMinY
oldDownRange = oldMaxY - centerY
newMinY      = centerY - oldUpRange   * 1.5
newMaxY      = centerY + oldDownRange * 1.5
```

이것은 전체 높이를 기존의 **1.5배**로 만드는 변경이며 2배가 아니다. 예를 들어 중심 50%, 기존 경계 25~75%라면 새 경계는 12.5~87.5%다. 이 수치는 설명용 예시이며 현재 코드의 값이 아니다.

### 화면 경계와 월드 경계를 분리할 것

현재 화면 내부의 제한만 좁다면 화면 내 이동 경계를 확장한다. 이미 화면을 넓게 사용한다면 월드의 높이와 카메라 추적을 조정해야 한다. 단순히 플레이어만 화면 밖으로 나가게 하지 않는다.

기체 크기, 이동 속도, 히트박스를 처음부터 함께 바꾸지 않는다. 일괄 줌아웃으로 해결하지 않는다. 카메라가 필요하면 중앙의 작은 회피는 안정적으로 보이고 큰 고도 변화만 부드럽게 따라가게 한다. 과한 카메라 지연으로 탄막 회피가 흐려져서는 안 된다.

지상과 구름은 고도에 맞춰 구성과 상대 위치가 자연스럽게 변해야 한다. 사용자가 잘 됐다고 한 지상 에셋과 표현은 유지한다. 확장된 모든 영역의 배경 커버리지를 확보한다.

### 통과 조건

상단/하단에서 기체가 잘리거나 HUD 뒤로 숨지 않는다. 확장된 공간에서도 적·탄환·아이템의 생성/제거·충돌 좌표가 일관적이다. 보이지 않는 적의 근거리 즉발 공격이 새롭게 발생하지 않는다. 화면 크기를 바꿔도 이동 여유가 크게 달라지지 않는다.

## 2. 구름: 질감 보정 전에 큰 형태와 공간 구성부터

참조 프레임:

- `references/ref_000s_ground.jpg`: 지상의 넓은 숲과 하늘의 관계.
- `references/ref_025s_cloud_volume.jpg`: 밝은 상부, 푸른 음영, 크고 작은 덩어리의 계층이 있는 구름.
- `references/ref_040s_sky_opening.jpg`: 큰 구름과 지상 사이의 넓은 하늘 여백.
- `references/ref_090s_cloud_layers.jpg`: 구름 덩어리의 겹침과 깊이감.

원본이 실제 볼륨 렌더링인지, 이미지 레이어인지 영상만으로 단정하지 않는다. 재현할 것은 내부 기술이 아니라 보이는 결과다.

### 시각 기준

큰 구름 덩어리 안에 중간 덩어리와 작은 굴곡이 이어지는 계층적 실루엣을 만든다. 같은 크기의 둥근 구름을 일렬로 늘어놓지 않는다. 밝은 부분과 푸른 회색 음영으로 부피를 보여준다. 본체 전체를 반투명 안개로 만들거나 모든 경계를 균일하게 흐리지 않는다.

원경·중경·근경은 크기, 대비, 세부 묘사, 움직임이 달라야 한다. 원경은 약하고 느리며, 중경이 주요 덩어리와 풍경을 만들고, 근경은 드물게 지나가 깊이를 보탠다. 모든 레이어를 같은 속도로 움직이지 않는다.

좁은 중앙 띠에만 구름을 반복시키지 않는다. 고도와 구간에 따라 지상, 구름 덩어리, 넓은 푸른 하늘이 차지하는 비율을 변주한다. 단, 특정 하늘 여백 비율을 모든 프레임에 기계적으로 강제하지 않는다.

### 구현 선택

현재 엔진을 유지하면서 가능한 접근을 비교한다. 현재 표현이 원/타원 중첩에 머물러 있다면, 도형 수·블러만 늘리는 작업을 반복하지 않는다. 질 좋은 독립 구름 텍스처/스프라이트와 다중 레이어 이동을 결합하는 방식을 우선 검토한다. 이미지 자산이 필요하면 필요한 규격과 역할을 제시하고 사용자 승인을 받는다. 실시간 3D 볼륨 구름부터 새로 구축하지 않는다.

먼저 대표 구름 한 장면의 품질을 승인받은 뒤 반복 타일·변형을 확장한다. 카드의 직사각형 경계, 후광, 동일 패턴의 빈번한 반복, 과도한 늘어짐이 보이면 통과시키지 않는다.

### 전투 가독성

구름 때문에 적탄의 위치와 플레이어의 피격 위치가 사라져서는 안 된다. 전경 효과를 쓰더라도 중요한 게임플레이 표시는 가리지 않게 렌더 순서와 대비를 관리한다. 예쁜 정지 화면뿐 아니라 가장 밝은 구름 위의 실제 회피 장면으로 검증한다.

## 3. 난이도: 단순 전체 배율보다 완만한 단계와 상한

기존 난이도/스폰 코드를 유지하면서 조정 가능한 설정으로 분리한다. 새로운 복잡한 적응형 AI부터 만들지 않는다.

적 수, 적 발사 빈도, 패턴당 탄수, 탄속, 체력을 한꺼번에 같은 비율로 올리지 않는다. 설명용으로 발사 적 수·발사 빈도·탄수가 각각 1.5배라면 초당 생성 탄수는 `1.5 × 1.5 × 1.5 = 3.375배`다. 이는 실제 난이도가 정확히 3.375배라는 의미가 아니라, 여러 상승 변수가 곱으로 겹칠 수 있다는 예시다.

### 1차 테스트용 페이스 제안

아래는 장르의 검증된 정답이 아니라 이 게임에 시험할 초기 설정이다. 실제 적의 체력과 처치 시간에 맞춰 보정한다.

| 구간 | 목표 | 공격 규칙 출발점 |
|---|---|---|
| 0~60초 | 조작, 풍경, 기본 무기 이해 | 직선/단순 공격 중심. 동시에 패턴을 실행하는 공격원 1개부터 |
| 1~3분 | 업그레이드 체험과 가벼운 회피 | 공격원 약 2개. 3방향 같은 단순 패턴을 순차 도입 |
| 3~5분 | 여러 패턴을 읽고 피하기 | 공격원 약 3개. 새 패턴은 기존 패턴과 바로 최대 중첩하지 않음 |
| 5분 이후 | 숙련 생존과 변주 | 공격원 약 4~5개를 출발점으로 시험. 탄속·탄수에는 상한 유지 |

'공격원 수'는 화면에 존재하는 모든 적 수와 다르다. 같은 프레임의 일제 발사 수와 조합을 관리하기 위한 기준이다. 몸통 충돌을 일으키는 적 밀도도 별도로 제한한다.

중간 이후에는 예컨대 전투 20~30초 후 5~8초간 생성·공격 압력을 완화하는 리듬을 시험한다. 완화는 기존 탄환을 갑자기 삭제하거나 게임을 멈추는 것이 아니다. 빠른 탄속, 좁은 안전 통로, 유도 공격을 한꺼번에 중첩하지 않는다.

작은 적의 체력을 계속 키워 처치가 늦어지고 화면에 쌓이는 상황을 피한다. 무기 강화가 체감되는 처치 시간을 유지한다. 플레이 공간을 확장한 직후에는 그에 비례해 적 밀도를 자동으로 올리지 않는다.

첫 획득 체험을 너무 늦게 하는지도 기록한다. 15~25초 안에 첫 업그레이드를 경험하는 테스트 설정은 제안할 수 있지만, 기존 획득 규칙 변경은 별도 확인 후 적용한다.

### 기록할 값

동일 시드에서 30/60/120/180/300초의 생존 적 수, 패턴 실행 공격원 수, 활성 적탄 수, 탄속, 플레이어 피격 횟수, 업그레이드 체류 시간을 기록한다. 사망 원인을 탄속, 동시 공격, 화면 가림, 경계, 처치 지연으로 나눠 본다. 무적 모드는 시각/부하 테스트에만 사용하며, 밸런스가 좋다는 증거로 쓰지 않는다.

### 오디오 구현 기준

현재 엔진의 오디오 기능이 충분하면 그대로 활용한다. 별도 오디오 라이브러리 교체부터 하지 않는다. 이벤트별 후보 2~3개를 개발용 청음 화면에서 비교하고, 연사·다중 적 피격 상황에서도 확인한다.

기본 발사음은 짧고 선명하게, 적 피격은 '맞혔다'는 작은 충격으로, 적 파괴는 그보다 분명하게, 플레이어 피격은 위험을 즉시 알 수 있게 구분한다. 단순한 전체 볼륨 증가로 처리하지 않는다. 피격음과 획득음이 연사에 묻히지 않도록 우선순위를 둔다.

한 발사 이벤트에서 탄이 여러 발 생성되어도 같은 발사음을 탄 수만큼 중복 재생하지 않는다. 빠른 연속 타격음에는 소리만의 재생 간격과 동시 발음 상한을 둔다. 게임의 실제 데미지 빈도를 줄여서는 안 된다. 음악/발사/피격/UI의 볼륨 경로를 분리한다.

짧은 효과음은 로드·디코드 후 재사용 가능한 버퍼로 관리하고 발사 때마다 네트워크 로드하지 않는다. 시작 조작에서 오디오 컨텍스트를 적절히 시작/재개한다. Web Audio의 이런 방식은 MDN에서 설명한다.
https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices

음악 작곡과 음원은 유지한다. 동시 재생의 클리핑이 실제로 있으면 우선 게인과 발음 수를 조정한다. 컴프레서는 추가 검토 사항이지 부실한 믹싱을 숨기는 기본 해결책이 아니다.
https://developer.mozilla.org/en-US/docs/Web/API/DynamicsCompressorNode

## 5. 무기 HUD와 효과음을 하나의 실제 상태에 연결

공개 페이지 텍스트에는 ENERGY, 점수, WARDEN 등이 보이지만, 이것만으로 캔버스 내부에 무기 표시가 없다고 단정할 수는 없다. 실제 구현을 먼저 확인한다. 사용자 요구는 현재 무기와 남은 시간을 항상 이해할 수 있게 하는 것이다.

기존 중앙 HP/스코어 그룹 아래에 작은 무기 상태 행을 추가한다. 플레이어 근처의 중앙 전투 화면을 큰 팝업으로 가리지 않는다.

```text
ENERGY [--------------------]
          SCORE 012345
[무기 아이콘] LASER     12.4s
              [=======---]
```

LASER는 예시다. 실제 무기 목록을 사용하며, 이 지시를 이유로 새 무기를 만들지 않는다. 기본 무기는 기본 무기 아이콘과 무제한 상태를 표시한다. 무기별 아이콘 형태·짧은 이름·남은 시간·게이지를 함께 사용해 색상만으로 구분하지 않게 한다.

획득 시 짧은 상승 계열 큐와 아이콘 강조, 만료 직전 3초 정도의 절제된 시각 강조, 만료 시 약한 해제 큐를 제안한다. 경고를 매 프레임 반복 재생하지 않는다. 기본 무기로 복귀한 사실도 표시한다.

### 상태 일치

무기 동작, HUD, 발사음, 피격음이 서로 다른 타이머나 복제 상태를 참조하지 않게 한다. 현재 프로젝트의 실제 무기 상태를 단일 기준으로 사용한다.

```text
remaining = max(0, expiresAtSimulationTime - currentSimulationTime)
gauge = clamp(remaining / currentGrantedDuration, 0, 1)
```

표시용 CSS 애니메이션이나 별도 wall-clock 타이머를 실제 지속 시간으로 사용하지 않는다. 일시정지·탭 비활성화 정책과 맞춰 게임 시간, 난이도, 무기 시간이 일관적으로 정지/재개되어야 한다.

중복 획득이 갱신인지 연장인지, 다른 무기 획득이 교체인지 중첩인지 실제 규칙을 확인하고 유지한다. 누적 시간이 있다면 그 규칙에 맞는 게이지 분모를 사용한다. 다중 무기가 동시에 적용되는 게임이라면 한 슬롯에 잘못 덮어쓰지 않고 작은 복수 슬롯을 표시한다.

### 무기별 발사/명중 피드백

실제 무기마다 발사음과 명중음 역할을 매핑한다. 기본탄, 확산탄, 연속 레이저, 미사일은 설명용 분류이며 존재하는 무기만 처리한다. 확산탄은 탄 수만큼 중첩한 소리가 아니라 한 번의 풍부한 발사음으로 표현한다. 연속 빔이 실제로 존재하면 시작·유지·종료를 나누며, 펄스 레이저를 무조건 루프 처리하지 않는다.

특히 **발사된 탄환에 원래 무기 종류를 보존**한다. 무기가 교체된 뒤 예전 탄이 적중해도 새 현재 무기의 명중음이 아니라 그 탄의 무기 기준 효과를 적용해야 한다.

루프 음원이 있다면 교체·만료·죽음·일시정지·재시작에서 모두 종료/재개 정책을 검증한다. 플레이어 피격은 실제 HP 감소 이벤트에 맞춰 재생하고 무적 중 충돌 판정마다 반복하지 않는다. 적 파괴음도 실제 파괴에 한 번만 발생하도록 한다.

## 6. 구현 순서와 제출물

1차: 이동 경계·카메라. 전후 경계 수치와 상단/중앙/하단 화면을 제출한다.

2차: 구름. 같은 위치·조건의 비교 화면과 20~30초 이동 영상을 제출한다. 정지 장면과 전투 가독성을 각각 검증한다.

3차: 난이도. 기존 설정과 수정 설정의 표, 동일 시드의 초기 5분 로그를 제출한다. 단순 클리어 여부보다 압박이 급격히 증가하는 원인을 제시한다.

4차: 무기 HUD·효과음. 실제 무기를 모두 순환하며 획득→발사→명중→재획득→교체→만료→기본 복귀→일시정지→재시작을 검증한다. 사용한 음원과 출처/라이선스를 제출한다.

각 단계에서 기존 지상, 음악, 조작 기능이 보존됐는지 확인한다. 목표 기기에서 부하를 측정하되 측정하지 않은 FPS를 보고하지 않는다. 데스크톱과 태블릿 가로 화면에서 상하 경계와 HUD 잘림을 비교한다. 브라우저에 접근할 수 없으면 그 사실을 쓰고 플레이 검증 완료라고 보고하지 않는다.
