# SkyWind 효과음 제작·검토 도구 설계

문서판: **검토 초안 3 / 2026-09-08 KST / 자율 오디오 평가·텐션 변형 반영 / 구현 전**.

사용자는 효과음의 품질을 높이기 위해 Codex가 직접 소리를 만들고 검토하는 스크립트 또는 앱이 가능하면 채택하겠다고 했다. 이 문서는 그 가능성, 실제 한계, 추천 구성을 정한다. 문서 전체 승인 전에는 도구 코드와 새 효과음을 만들지 않는다.

[1차 전투 감각 확인본](FIRST_IMPLEMENTATION.md)은 기존 게임 오디오 경로의 사건별 변형으로 먼저 플레이하는 제안이다. 이 제작 도구나 외부 평가기의 실증을 1차의 선행 조건으로 삼지 않는다. 도구 자체는 후속 미구현 상태로 남기며 1차 청음 결과를 자율 제작 품질의 실증으로 기록하지 않는다.

## 1. 현재 판단과 채택 상태

**레시피 기반 효과음 생성, 반복 제작, 기술 분석, 비교 재생 도구는 제작 가능하다.** 현재 설치된 Node.js·FFmpeg와 브라우저를 이용하는 소규모 로컬 도구를 추천한다. 게임 실행에 새 의존성을 넣을 필요는 없다.

다만 도구를 만들었다는 사실만으로 음색의 품질이 개선되지는 않는다. 좋은 기준 음색, 역할에 맞는 레시피, 실제 연사·혼합 비교가 필요하다.

현재 Codex에 연결된 도구에는 효과음 원본을 입력받아 음색을 평가하는 수단이 확인되지 않았다. 그러나 추가 조사에서 Gemini의 비언어 오디오 이해와 Qwen의 오디오 분석 모델을 확인했다. **별도 오디오 모델을 평가기로 연결하여 후보 제작 → 실제 음원 입력 → 평가 → 수정 반복을 자동화하는 경로를 제안할 수 있다.** 공식 입력 기능 확인과 SkyWind 효과음 품질 개선의 실증은 다른 상태다.

사용자는 대표 후보를 직접 고르는 제안보다 **완전 자율 청음이 가능한 방법의 추가 조사**를 선택했다. 따라서 최초 사용자 청음을 필수 선행 조건으로 채택하지 않는다. 현재 추천은 오디오 평가 모델의 신뢰성을 먼저 확인한 뒤 기준 음색과 변주를 자동 비교·선정하는 방식이다. 평가 모델·연결·비용/반복 한도·채택 기준은 R17의 미결 선택이며 아직 호출·설치·품질 실증은 하지 않았다.

## 2. 현재 재사용할 수 있는 기반

- assets/audio/sfx-patch1/prepare_sound.py에는 원본 크롭·필터·레이어 혼합·엔벌로프·WAV 출력·측정 절차가 있다. 기존 편집본을 만든 근거이며 새 고품질 음색이 이미 만들어졌다는 뜻은 아니다.
- 해당 스크립트는 NumPy를 요구한다. 이번에 확인한 기본 Python 3.13 환경에는 NumPy·SciPy가 없으므로 현재 그대로 실행 가능하다고 쓰지 않는다. 이번 조사에서 설치나 실행은 하지 않았다.
- Node.js와 FFmpeg/FFprobe는 사용 가능하다. 새 도구의 추천 경로는 Node로 합성/레시피를 관리하고 브라우저로 비교하며 필요할 때 FFmpeg로 분석·변환하는 방식이다.
- 기존 효과음 원본·편집본·provenance는 보존한다. 새 제작을 위해 기존 prepare_sound.py나 최종 샘플을 덮어쓰지 않는다.

## 3. 최소 도구 구성 추천

게임과 별도로 로컬에서 실행하는 제작 화면과 배치 스크립트를 한 묶음으로 만든다. 같은 레시피가 같은 제작 경로를 사용하도록 하고, 화면용 합성기와 배치용 합성기를 서로 다른 구현으로 만들지 않는다.

| 구성 | 역할 |
|---|---|
| 오프라인 합성 스크립트 | 고정 시드·레시피로 PCM을 생성하고 WAV 후보를 저장 |
| 레시피 파일 | 음원 층, 주파수/피치 곡선, 엔벌로프, 필터, 왜곡, 공명, 게인, 길이·시드 |
| 로컬 비교 화면 | 후보 A/B/C 재생, 같은 청감 크기의 비교 보조, 층별 듣기, 단발/연사/혼합 장면 |
| 분석기 | 파형·스펙트럼·피크·RMS·DC·무음·길이·끝점·클리핑·중복 파일 확인 |
| 오디오 평가 연결 — 검토안 | 실제 음원 파일을 오디오 모델에 전달하고 역할·질감·연사·혼합 평가를 받음. 구현 전에 평가기 자격 검사 필요 |
| 승인·출력 기록 | 후보/반려/기준 음색/채택 변주, 사용 레시피·해시·실행 파일 경로 기록 |

미래 경로의 제안은 tools/sfx-workbench/ 아래의 생성기·서버·비교 화면과 assets/audio/sfx-mecha/ 아래의 recipes·candidates·approved다. 현재 존재하는 경로가 아니다. 실행본에는 채택된 음원과 게임이 필요한 매핑만 포함하고 제작 서버·후보·분석 화면은 배포하지 않는다.

기존 npm 개발 서버와 별도 포트를 확인하여 실행한다. 로컬 제작 서버는 127.0.0.1에서만 열고, 임의 셸 명령이나 임의 파일 경로를 입력받는 서버로 만들지 않는다. 큰 DAW·범용 음원 관리 앱·사용자 계정 시스템은 범위에 없다.

## 4. 소리의 구성 방식

루미네스를 참조한 전자음의 즐거움과 건담 00을 오마주한 메카닉 전투를 함께 지향한다. 실제 곡의 박자나 조성에 맞추는 기능은 필요하지 않다. 음정 있는 소리를 사용할 경우 효과음끼리의 조화와 배경 음악 위에서의 혼합을 청음으로 판단한다.

| 층 | 역할 | 제어할 값 |
|---|---|---|
| 시작 타격 | 입력·접촉이 즉시 느껴지는 짧은 시작 | 상승 시간, 노이즈/클릭 비율, 고역의 강도 |
| 에너지 몸통 | 무기별 정체성과 무게 | 기본 파형, 주파수 곡선, FM/AM의 깊이, 지속시간 |
| 기계 재질 | 장갑·발사구·기믹의 단단함 | 필터 노이즈, 금속성 공명, 짧은 재질 샘플의 혼합 |
| 여운 | 빛의 확산과 끝맺음 | 감쇠, 제한된 지연·공명, 종료 길이 |

전자음은 파형 하나를 무작위로 찍어내는 방식으로 끝내지 않는다. 목표 역할에 맞춰 위 층을 설계하고 불필요한 층은 줄인다. 샘플을 섞을 때는 기존 사용 가능한 원본 중 목적에 맞는 것을 고르며, 새 외부 서비스·유료 플러그인·모델 다운로드를 자동 전제하지 않는다.

합성 시 거친 왜곡·급격한 피치 이동에서 생기는 불필요한 고역과 끝점의 클릭을 검사한다. 필요한 경우 오프라인 처리에서 필터·오버샘플링을 적용하는 안을 검토하되, 비용과 구현 난도가 불필요하게 커지는 범용 신시사이저를 만들지 않는다.

## 5. 처음 만들 기준 음색

먼저 **발사·명중·격파의 대표 3종**을 각각 다른 설계 방향의 후보 3개로 제안한다. 총 후보는 설명상 `3종 × 3안 = 9개`이며 최종 생산 수량의 확정이 아니다.

- 발사: 또렷하고 탄력 있는 에너지 발사, 가늘고 절제된 전자 발사, 조금 무게 있는 메카닉 발사.
- 명중: 밝은 접촉, 단단한 장갑 접촉, 노출된 에너지 핵 접촉.
- 격파: 짧은 빛의 파열, 단단한 기체 붕괴, 두 요소를 결합한 에너지 확산.

단발로 좋은 후보도 연사에서는 거슬릴 수 있다. 기준 선정에는 단발과 실제 발사 간격의 반복을 함께 제공한다. 무기별 세부 음색은 채택한 계열 안에서 벌림·집중·진동·보조 사격의 역할에 맞춰 파생한다.

대표 기준이 확정되면 기본·SPREAD·LANCE·HELIX·드론, 가벼운/장갑/약점 명중, 일반/중간급/보스 격파, 적 발사, 기믹 개폐, 획득/만료/피격 큐의 필요한 종류를 최종 제작 목록으로 확정한다. 단순히 총 파일 수를 채우는 것을 완료 기준으로 삼지 않는다.

[텐션업](BARRAGE_DESIGN.md)에 맞춰 같은 무기의 정상/텐션 발사음과 정상/강화 탄 명중음을 한 계열로 비교한다. 텐션 쪽은 시작 타격·에너지층·짧은 공명을 고조하되 음량 증가만으로 차이를 만들지 않는다. 시작·갱신·만료 큐는 별도 짧은 반응이며 연속 회피 시의 중복 억제를 함께 설계한다. 구체 레시피는 R15·R20에서 검토한다.

## 6. 비교 화면의 필수 동작

1. 후보의 이름·역할·길이·레시피 버전·선택 상태를 표시한다.
2. A/B/C를 같은 조건에서 전환하고, 층을 각각 듣거나 전체 혼합으로 듣는다.
3. 단발, 일정 시간의 연사, 적 명중이 겹치는 연사, 연속 격파, 보스/잡몹/피격이 겹치는 장면을 재생한다. 정상→텐션 시작→반복 갱신→만료와 텐션 중 피격을 포함하고, 무기별 단발·연사·고밀도 혼합을 비교한다.
4. 게임에 사용할 실제 파일과 실제 발사 간격·동시 재생 제한·게인으로 혼합한다. 별도 데모가 게임보다 과장되거나 더 조용하게 들리는 상태를 방지한다.
5. 배경 음악을 켜거나 끄며 충돌·경고의 식별성과 피로감을 비교한다. 음악 시계·BPM 동기화는 없다.
6. 정지·반복·후보 전환에서 옛 소리가 남지 않게 한다. 후보를 들은 것과 선택한 것은 다른 상태로 기록한다.

청감 크기 비교 보조는 미리듣기에만 적용할 수 있다. 원본 파일이나 최종 게인을 몰래 정규화하지 않는다. 짧은 효과음을 하나의 LUFS 목표로 일괄 통과시키지 않고 단발 피크와 실제 반복/혼합 결과를 함께 확인한다.

## 7. Codex가 수행할 자동 검토

| 검사 | 걸러낼 수 있는 문제 | 판정하지 못하는 것 |
|---|---|---|
| 길이·파일 형식·샘플레이트·채널 | 잘못된 내보내기, 무음/빈 파일, 로딩 불일치 | 음색의 매력 |
| 피크·클리핑·DC·끝점 | 넘침, 비정상 오프셋, 클릭 가능성 | 거친 음색의 의도와 피로감 전체 |
| 파형·스펙트럼·시간별 에너지 | 지나치게 긴 꼬리, 대역 편중, 단발/반복의 누적 | 사람에게 들리는 타격감·쾌감 |
| 기준과 레시피/해시 대조 | 실수로 다른 후보 채택, 변주가 기준을 벗어남, 중복 | 새 기준 음색의 최종 선택 |
| 실제 간격의 혼합·보이스 검사 | 지나친 중복, 잘리는 큐, 무한 누적, 정지 잔류음 | 음악과 어울리는 최종 청감 |

자동 점수 하나로 '루미네스적이다' 또는 '고품질이다'라고 승인하지 않는다. 코드로 계산한 수치·음원 없이 작성한 설명·브라우저 재생 버튼 실행은 오디오 입력에 근거한 평가가 아니다. 오디오 모델이 실제 파일을 입력받은 경우에도 이를 사람이 직접 청음한 기록으로 표시하지 않는다.

대표 음색 선정 후에는 승인된 특성을 크게 벗어나지 않는 변주를 자동 생성·기술 검사하고, 경계 후보와 실제 혼합 장면을 우선 검토 대상으로 추린다. 실패 원인은 레시피와 함께 남겨 같은 결함을 반복 생산하지 않는다.

| Qwen3-Omni-30B-A3B-Captioner | 영화 효과음·음악·환경음의 세부 묘사. 단일 오디오 입력만 허용하고 텍스트 지시는 받지 않음 | 소리가 실제로 어떻게 들리는지 독립 묘사하는 보조 후보. 평가 기준을 지시하는 A/B 심사 모델로 그대로 사용할 수 없음. 설명을 Codex가 해석하는 간접 단계임 |
| Qwen2-Audio-7B-Instruct | 오디오와 텍스트 지시를 함께 받아 소리·음악 분석 | 로컬 실행이 필요한 경우의 작은 모델 후보. 양자화·CPU 분산·처리 속도·짧은 전자 효과음 분별력은 현재 장비에서 미검증 |

Gemini 공식 문서는 다채널 오디오를 단일 채널로 합치고 입력을 다운샘플한다고 설명한다. 따라서 스테레오 공간감이나 원본의 미세한 고역 결함까지 해당 모델 응답 하나로 통과시키지 않는다. 원본 PCM의 채널·피크·대역·클릭 검사를 병행한다. [Gemini 공식 오디오 문서](https://ai.google.dev/gemini-api/docs/audio)

Qwen Captioner는 오디오 묘사를 위한 모델이며 좋은 게임 효과음을 고르는 성능이 검증됐다는 뜻은 아니다. 공식 문서도 짧은 입력을 권장하며 텍스트 프롬프트를 허용하지 않는다고 명시한다. [공식 모델 카드](https://huggingface.co/Qwen/Qwen3-Omni-30B-A3B-Captioner)

현재 PC는 RTX 3060 12,288MiB VRAM과 약 63.8GiB RAM을 확인했다. Qwen3-Omni의 공식 BF16 메모리 표는 대형 GPU 환경이며 영상 입력·Instruct/Thinking 모델 조건이므로 이를 Captioner 짧은 효과음의 정확한 필요량으로 복사하지 않는다. 현재 GPU에서 간단히 실행된다고 가정하지 않고, 로컬 모델 설치를 제작 도구의 기본 전제로 넣지 않는다. [공식 실행·메모리 안내](https://github.com/QwenLM/Qwen3-Omni)

공식 오디오 입력 기능에 근거한 **설계 추론**은 가능하나, 위 모델이 SkyWind의 취향·타격감·장시간 피로감을 정확히 판정한다는 실증은 아직 없다. 관련 연구에서도 오디오 모델의 환각을 별도 평가한다. 음성 품질 연구의 수치를 효과음의 품질 보증으로 옮기지 않는다. [HalluAudio 연구](https://aclanthology.org/2026.acl-long.1797/)

### 7.2 자동 반복의 구체 제안

1. **평가기부터 시험한다.** 기존 효과음의 임시 사본으로 무음·명백한 클리핑·급한 잘림·과도한 잔향·반복 누적 등의 알려진 변형을 만들고, 원본과 구분하는지 확인하는 실증을 계획한다. 정상 짝도 섞어 모든 소리를 결함으로 판정하는 평가기를 걸러낸다. 현재는 이 사본도 제작하지 않았다.
2. **파일을 실제로 입력한다.** 생성 의도나 레시피 설명만 보내지 않는다. 최종 후보 WAV와 게임 간격으로 만든 연사·혼합 클립을 전달하고 입력 파일 해시·모델 버전·응답을 연결한다. 후보 이름은 중립 ID로 숨긴다.
3. **조건을 맞춰 비교한다.** 단발과 연사에서 음색을 비교할 때는 음량 차이의 영향을 줄이고, 실제 혼합에서는 게임 게인을 유지한다. 보정값은 기록한다. A/B 순서를 바꿔 재평가하고 같은 파일 쌍도 포함해 위치 편향과 모순을 관측한다.
4. **역할별로 평가한다.** 시작의 명료함, 에너지/기계 재질, 연사 시 거슬림, 명중/격파의 구분, 경고를 덮는 정도를 분리한다. 들린 특징과 불확실성을 먼저 적고 개선 제안을 받는다. 정확한 밀리초·주파수·피크 수치는 모델의 추측 대신 분석기 값을 쓴다.
5. **작게 수정한다.** Codex는 지적된 항목에 대응하는 레시피 값만 바꾸고 새 후보를 만든다. 기존 최고 후보를 보존하며 같은 결함을 반복하면 방향을 바꾼다. 점수가 올랐다는 이유로 목표 역할이 바뀐 후보를 채택하지 않는다.
6. **반복을 제한한다.** 최대 후보·개선 라운드·호출 비용·시간을 R17에서 정한다. 기술 실패, 평가 모순, 일정 횟수 개선 없음, 한도 도달 시 그 상태와 최선 후보를 남긴다. 무한 재생성하거나 실패를 통과로 바꾸지 않는다.
7. **자동 채택의 의미를 기록한다.** 평가기 자격·기술 검사·최종 게임 혼합 기준을 통과하면 합의된 범위에서 자동 채택할 수 있게 설계한다. 이는 사용자 취향 승인이나 사람의 직접 청음과 구분한다. 청음이 불가능하다는 이유로 다시 사용자 후보 선택을 자동 필수화하지 않는다.

평가기 시험은 명백한 결함 검출과 비교 일관성을 확인하는 단계다. 이것만 통과해도 모든 예술적 품질을 판별한다고 결론 내릴 수는 없다. 평가가 불안정하면 자율 품질 개선은 **미실증**으로 남기고 다른 평가기나 기준을 검토한다.

클라우드 경로를 채택한다면 실제 파일을 해당 서비스에 보내며 계정 접근과 사용 비용이 발생할 수 있다. 이번 문서 조사에서는 자산 업로드·API 호출·키 조회·모델 다운로드를 하지 않았다. 구현 단계에는 선택한 서비스와 호출 한도를 먼저 구체화하며 인증정보는 제작 서버 내부에서만 사용한다.

## 8. 채택·게임 연결

- 제작 기본 포맷은 기존 편집 파이프라인과 맞는 48kHz PCM WAV를 제안한다. 비트 깊이·채널·길이·게인 목표는 기준 음색과 실제 브라우저 디코딩 확인 뒤 확정한다.
- 원본/레시피 → 후보 → 선정된 기준 → 변주 → 최종 채택 파일의 관계를 기록한다. 채택 파일을 같은 이름의 새 후보로 덮어쓰지 않는다.
- 게임의 src/audio.js에 필요한 그룹·이벤트·무기/대상 매핑을 연결한다. 플레이어 피격과 경고는 보상음보다 식별 우선순위를 유지한다.
- 탄수 증가 때문에 동일한 발사음을 탄마다 중복 재생하지 않는다. 적탄도 발사 묶음의 소리를 사용한다.
- 강화 탄의 명중음은 발사 시 저장한 텐션 정보를 따른다. 텐션이 끝난 뒤 도착한 탄도 해당 피해/명중음 변형을 유지한다. 체인·약점·텐션이 겹친 혼합에서는 보이스 예산과 경고 우선순위를 공유한다. 모델의 음색 비교와 이 이벤트 경계 검사는 따로 기록한다.
- 기존 버스·보이스 제한·무음/정지/종료 처리는 필요한 범위에서 연결·수정하고 실제 반복 장면으로 검증한다.
- 효과음 제작 앱이 없어도 최종 게임은 채택된 정적 음원으로 실행되어야 한다.

## 9. 미결 선택

**R17 개정:** 사용자는 완전 자율 청음 경로의 추가 조사를 선택했다. 사람의 최초 후보 선택을 기본안으로 채택하지 않는다. 현재 추천은 Gemini 오디오 평가의 소규모 실증이며, 모델/계정 접근·평가기 자격 기준·반복/비용 한도·자동 채택 범위는 아직 확정하지 않았다. 로컬 Qwen 경로는 대안으로 조사했으며 설치·실행되지 않았다.

오디오 입력 가능한 모델의 존재는 확인했다. 현재 환경에서 평가 연결과 반복 개선이 실제로 동작하고 효과음이 좋아졌다는 결론은 실증 이후에만 내린다. 이 한계를 이유로 독립적인 메카닉 문서 정리를 멈추지는 않는다.

관련 합격 기준은 QUALITY의 V35·V38·V39~V41·V47~V49다. 현재는 도구 구성·외부 오디오 평가 경로·검토 한계를 문서화했으며, 소리 제작·도구 실행·품질 개선의 실증은 아직 하지 않았다.
