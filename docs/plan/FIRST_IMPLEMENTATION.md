# SkyWind 1차 구현 항목 — 전투 감각 확인본

문서판: **2026-09-08 KST / D42 승인 범위의 로컬 코드 구현 반영**.

**현재 상태:** I01~I07과 후속 R2~R6를 실제 게임 코드에 적용했다. 최신 범위와 검증은 [작업 보고서](../WORK_REPORT_20260909.md), R1 당시 관측은 [1차 구현 결과](../first-implementation/README.md)를 따른다. 이 문서는 승인된 포함 범위와 시험값의 기준이며, 아래 구현 전 기반·순서는 출발 당시 설계 기록으로 읽는다. 다른 환경에서는 [1차 구현 후 인계 안내](../../FIRST_IMPLEMENTATION_HANDOFF.md)를 따라 현재 변경본을 확인한다. Git 게시·보고서 첨부는 D49로 별도 승인받았으며 공개 배포와 전체 제작은 포함하지 않는다.

## 1. 이번 결과물

**루미네스적인 발사·명중 반응, 큰 상하 이동과 작은 탄막 회피, 45초 일반전+보스전, 낮밤·가속, 2초 텐션과 탄막 4종을 한 번에 플레이할 수 있는 로컬 확인본**을 실제 시작·전투·피격·게임오버·재도전에 연결했다. 원하는 손맛·음질의 최종 사용자 승인은 구현 사실과 구분한다.

초기 범위 정리 요청 뒤 사용자는 D42에서 “구현 안내에 따라 구현 진행. 질문이 필요한 부분은 물어보지 않고 우선판단으로 구현”을 지시했다. 이에 아래 시험값·기존 자산 재사용·첫 두 사이클을 기준으로 로컬 구현을 진행했다. 남은 전체 아트·제작 도구·최종 밸런스 결정은 선행 조건으로 강제하지 않았다.

첫 확인의 중심은 **1·2사이클**이다. 첫 사이클의 화려하지만 쉬운 회피 → 두 번째의 조준 압박 → 보스 격파 후 다시 낮으로 돌아오는 흐름을 완성한다. 무한 진행은 유지하되 3사이클 이후에는 두 번째 난도에서 두 보스를 번갈아 반복하는 확인용 범위를 제안한다. 3~6사이클의 추가 상승과 최후반 극한 조합은 이 첫 결과물을 검토한 뒤 다룬다. 이는 최종 게임의 D37 난도 목표를 삭제하거나 완성했다고 처리하는 것이 아니다.

상하 예고의 시각 방향은 사용자 첨부를 반영한 **헬멧 바이저에 투사된 듯한 곡선 HUD**다. 화면 위아래를 감싸는 얇은 발광 호와 위/아래 방향 표식, 서로 다른 방향색을 사용한다. 아이템 종류·초읽기는 호에 연결된 작은 라벨이다. 상단 노랑/앰버·하단 초록/민트는 첫 비교 제안이며 정확한 이미지 복제는 하지 않는다. [P01 상하 보급 예고](IMPLEMENTATION.md)의 형태·상태·크기 규칙을 따른다.

| 일반전 시각 | 전투·이동 | 빛·소리·속도에서 확인할 점 |

| 보스전 | 실제 보스 공격·텐션·격파, 살아 있으면 계속 전투 | 밤·3배 속도·발사/명중 고조, 격파 후 낮과 기본 속도로 복귀 |

보급 시각 표는 첫 일반전 기준이다. 이후에는 보스 처치 시간에 관계없이 조작 가능한 게임 시간의 보급 일정이 이어진다. 보스 진입/격파 때 보급 시간을 리셋하지 않는다. 보급 도착 지점을 몸통·탄막으로 계속 봉쇄하지 않는다.

## 6. 구현 순서와 변경할 코드 영역

아래는 한 번의 1차 구현 안에서 이어갈 순서다. 행마다 따로 구현 승인을 요구하는 순서가 아니다.

1. **기준 확보와 구간 상태:** 현재 소스·로컬 화면을 확인하고 I01을 구현한다. 일반전/보스 시간, 정지·재도전, 1차 난도 행과 보스 순서를 연결한다.
2. **시각 템포:** I02의 배경 누적 거리·속도 곡선과 낮밤을 연결한다. 이 단계에서 실제 상하 이동 시 구름·지형·기체가 보이는지 확인한다.
3. **상하 선택:** I03의 성장/무기 시간·보급·예고·회복을 붙인다. 탄막 전후의 정상 입력 도달성을 각각 확인한다.
4. **근접 보상:** I04의 충돌/근접·피해·탄 정보·기본 게이지를 먼저 붙인다. 실제 텐션 상태를 패턴/연출 조정의 기준으로 삼는다.
5. **패턴과 보스:** I05의 4패턴·조준·전체 시퀀스 예산을 연결하고 첫/두 번째 배치를 만든다. 첫 패턴을 보여 주기 위해 적을 강제 무적으로 만들지 않는다.
6. **빛·소리 통합:** I06의 정상/텐션 발사·적 명중·격파·체인 반응을 실제 사건에 연결한다. 혼합 재생과 적탄 가독성을 함께 조정한다.
7. **플레이·회귀 확인:** I07을 완료하고 실행 가능한 로컬 URL, 확인 순서, 실제 검사 결과와 미완성 영역을 전달한다.

예상 변경 책임은 다음과 같다. 실제 파일 분리는 구현 때 필요한 최소 범위로 확정한다.

| 코드 영역 | 1차 책임 |
|---|---|
| src/game.js, 필요 시 src/level.js | 상태/시간·난도·보급/성장·텐션·4패턴·조준·보스·초기화 |
| src/renderer.js | 실제 탄/포구·핵·예고·강화색·사건별 효과, 기존 자산 연결 |
| src/volume-environment.js, src/terrain3d.js | 낮밤·조명색과 연속 배경 이동 |
| src/audio.js | 기존 음원/합성 경로의 사건별 변형·텐션·중복/보이스·정지 |
| src/presentation.js, src/main.js, index.html, style.css | 보급/성장/텐션/사이클 표시와 필요한 크기·입력 대응 |
| tests/, package.json, tools/build-site.mjs | 변경한 규칙의 의미 있는 검사, 새 모듈이 있으면 구문/실행 목록 연결 |

새 개발 서버·게임 엔진·대형 의존성·범용 설정 앱은 필요하지 않다. 공개 사이트는 이 1차 로컬 확인본의 자동 배포 대상이 아니다.

## 7. 1차에서 보류하는 범위와 기존 설계의 관계

- **새 Blender 적·보스와 약점/장갑 애니메이션:** 제작하지 않는다. 기존 스프라이트를 이 확인본에서 사용하는 제안은 새 메카닉의 최종 승인/채택을 뜻하지 않는다. 새 모델로만 가능한 부위 파괴·약점 피해도 이번에는 넣지 않는다.
- **효과음 제작 앱·자율 오디오 평가기:** R17 조사·연결·모델 다운로드를 첫 플레이 확인의 선행 조건으로 두지 않는다. 기존 음원의 사건 연결과 변형으로 방향을 확인하며 최종 음색 품질을 해결했다고 보고하지 않는다.
- **3~6사이클 최종 상승·극한 난도 완성:** 이 확인본에는 첫/두 번째 패턴 값만 넣는다. 반복 플레이의 안정성과 두 번째 압박은 검증하되 최후반 생존성까지 통과했다고 주장하지 않는다.
- **신규 적/보스 역할·새 지역·새 무기·전면 HUD 재디자인:** 보류한다. 기존 적 역할, 상하 선택에 필요한 무기 성장, 보급/텐션을 읽는 최소 HUD를 사용한다.
- **음악 직접 연계·BGM 교체:** 포함하지 않는다. 현재 음악 전환의 흐름을 유지하고 사건 효과음과의 혼합을 확인한다.
- **커밋·푸시·공개 배포:** 첫 구현 지시의 자동 포함 범위가 아니다.

이 한정 범위를 D42로 승인받아 I01~I07을 구현했다. 1차 구현 승인만으로 남은 전체 제작에 자동 착수하지 않는다. 최종 완성본은 [전체 구현 설계](IMPLEMENTATION.md)의 나머지 범위와 별도 상태로 관리한다.

## 8. 첫 결과물의 합격 기준

| 확인 묶음 | 1차 합격 기준 | 연결된 기존 검증 |
|---|---|---|
| 사이클·재시작 | 정상 플레이의 첫 두 보스와 다음 일반전 연결, 보스 장기 생존·정지·게임오버·재도전 정상. 추가 반복에서 개체/타이머 누적 없음 | V01~V10 중 1차 사양 적용 부분 |
| 상하 이동 | 기본·특수·드론 조합에서 보급 효과 정확. 정상 입력의 한쪽/양쪽 획득과 늦은 출발 비교. 상공/하층 카메라 정렬 | V11~V20 |
| 낮밤·HUD | 맑은 낮/밤과 가속·복귀 확인. 상하 호·방향색·아이템/시간 일치, 한쪽 종료 시 반대쪽 유지. HUD/텐션/적탄 핵·터치 입력 가림 없음 | V21~V28 중 음악 재배정 제외 |
| 텐션·패턴 | 근접 경계/동일 탄/피격/정지/발사 시 피해, 두 단계의 모든 패턴·3속도 조준·전체 시퀀스 예산·연속 회피 경로 | V50~V56의 첫/두 번째 단계 |
| 빛·소리 | 실제 사건과 빛/소리 일치. 정상/텐션 차이가 구분되고 연사·명중·격파 혼합에서 경고 보존. 음소거/정지/종료의 잔류음 없음 | V33·V34·V36~V38, 기존 오디오 회귀 검사 |
| 실행·성능 | npm test·check·build:site, 개발 서버/빌드의 실제 로딩·입력·콘솔·이미지. 같은 조건의 첫/두 번째 고밀도 프레임 시간·보이스 비교 | V30~V32의 해당 범위 |

새 메카닉 제작 V42~V46, 자율 오디오 평가 V39~V41·V47~V49, 극한 V57은 이번 합격 대상에서 제외하고 **후속 미수행**으로 기록한다. 새로운 손맛이나 청음의 사용자 승인을 자동 검사 결과로 대신하지 않는다.

최소 실제 확인은 첫 두 사이클의 정상 조작, 상하 보급 이동, 두 단계의 패턴별 통제 장면, 낮/밤의 대표 큰 화면과 작은 화면이다. 첫 두 사이클에서 보스가 빨리 격파되어 일부 패턴이 생략되면 검증용 상태에서 해당 패턴을 별도로 관측한다. 이 때문에 일반 플레이에 강제 대기나 디버그 메뉴를 추가하지 않는다.

전달할 결과는 **실행 중인 로컬 주소, 구현된 I01~I07 목록, 시험값 조정 내역, 실제 검증 증거, 사용자 확인 포인트와 남은 범위**다. 원래 57개 검증을 모두 통과한 전체 완성본으로 보고하지 않는다.
