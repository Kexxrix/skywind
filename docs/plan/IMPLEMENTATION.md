# SkyWind 전체 개선·화면·구현 설계

문서판: **검토 초안 7 / 2026-09-08 KST / 문서 게시·타 환경 인계 / 게임 구현 미시작**.

이 문서는 게임 레벨 디자인을 중심으로 UI·배경·연출·입력·사운드·자산·코드 연결을 함께 구현하기 위한 제안서다. 사용자가 확정한 방향과 인계 요청은 [결정 기록](DECISIONS.md)의 D01~D41이며, D09는 대체된 초기 해석이다. 아래 구체적인 디자인·수치·구현 방법은 전체 검토 대상이다. 초안 작성 완료만으로 게임 작업을 시작하지 않는다.

**현재 첫 실행 범위 제안은 [전투 감각 확인본](FIRST_IMPLEMENTATION.md)의 I01~I07이다.** 빛·소리·상하 이동·45초+보스·속도/낮밤·텐션·4패턴을 기존 자산으로 연결해 먼저 확인한다. 아래 전체 완성본의 메카닉·효과음 제작 도구를 첫 확인의 선행 조건으로 삼지 않는다. 시험값·한정 예외·첫/두 번째 난도·승인 상태는 FIRST_IMPLEMENTATION과 DECISIONS를 따른다.

진행·무기·보급·전체 난도 예산은 [레벨·전투·보급 설계](LEVEL_DESIGN.md)의 L01~L08, 근접 회피·텐션·개별 탄막 수치는 [탄막·텐션업 설계](BARRAGE_DESIGN.md)의 L09~L10에서 관리한다. 이 문서에서는 같은 전투 수치를 다시 정의하지 않는다.

## 1. 전체 결과와 범위

현재 SkyWind의 숲·구름·SV-01·파일럿을 기준으로 일반전·보스전·무기 성장·상하 보급을 하나의 흐름으로 만든다. 메카닉의 공통 디자인은 건담 00 오마주이며, 적·보스는 Blender에서 새로 모델링하고 애니메이션을 렌더한 스프라이트로 제작한다. 빛·소리는 루미네스를 참조한 사건 중심 반응을 사용하며 음악과 직접 동기화하지 않는다.

| 포함할 결과 | 담당 사양 | 완료 증거 |
|---|---|---|

## 2. 화면 크기와 HUD 제안 — P01

### 현재 문제와 기준

현재 중앙 상태 패널은 기본 216 CSS px이고 축소 규칙은 창 너비 700px를 기준으로 한다. 게임 화면은 보통 16:9이므로 가로로 긴 작은 창에서 실제 게임 너비가 700px 미만이어도 큰 HUD가 남을 수 있다.

예를 들어 844×390 창의 16:9 게임 영역은 `min(844, 390×16÷9) ≈ 693` CSS px다. 이는 소스의 크기 공식으로 계산한 예이며 해당 실기에서 직접 측정한 결과가 아니다. 앞으로는 **창 전체가 아니라 실제 영상이 그려지는 게임 사각형**을 기준으로 배치한다. 전체 화면의 검은 여백까지 게임 영역으로 계산하지 않는다.

### 반응형 크기 추천안

아래 너비·글자·버튼 단위는 CSS px다. 전투 좌표와 혼용하지 않는다.

| 요소 | 게임 너비 1280 이상 | 800~1279 | 800 미만 |
|---|---:|---:|---:|
| 중앙 상태 패널 너비 | 216 | 184 | 140 |
| 중앙 패널 상단 여백 | 20 | 14 | 8 |
| 점수 주요 숫자 | 16 | 14 | 13 |
| 무기 이름·레벨·남은 시간 | 11 | 11 | 11 |
| 드론 표시 글자 | 10 | 10 | 10 |
| 보스 게이지 너비 | 280 | 240 | min(190, 게임 너비의 48%) |
| 보스 게이지 하단 여백 | 40 | 28 | 12 |
| 터치 이동 영역 지름 | 92 | 82 | 72 |
| SHOT 버튼 지름 | 74 | 66 | 58 |

- 중앙 패널은 기존 HP → 점수/체인 → 주무기 → 드론의 정보 관계를 보존한다. 작은 화면에서는 세로 여백과 장식 라벨을 줄이고 필수 숫자는 읽을 크기로 유지한다.
- 텐션은 주무기 근처의 작은 독립 게이지로 표시하는 안을 제안한다. 2초 지속과 갱신이 읽혀야 하며 주무기/드론 시간·격파 체인과 구분한다. 화면 중앙 핵을 덮는 큰 숫자나 별도 파일럿 얼굴 상태는 추가하지 않는다. 표시의 확정은 R20을 따른다.
- 파일럿은 기존 왼쪽 고정·상단 비율·362:108 마스크를 유지한다. 너비는 `clamp(96px, 게임 너비×18.854167%, 362px)`를 제안한다. 그림과 프레임을 함께 조절하고 얼굴만 별도로 찌그러뜨리지 않는다.
- 게임 너비 640 미만에서는 파일럿의 장식 텔레메트리·영문 상태 자막을 숨기되 얼굴·색 상태·피격 표시를 남긴다.
- 유틸리티 버튼은 보이는 아이콘 형태를 유지하고 클릭/터치 영역을 44×44로 제안한다. 게임 너비 640 미만의 전투 화면에는 우상단 일시정지 하나만 두고, 음소거·전체 화면은 일시정지 패널에서 제공한다. 타이틀·결과 화면에는 세 버튼을 유지한다. **이 작은 화면의 재배치는 검토 대상이다.**
- 보스 게이지와 하단 보급 예고는 중앙에 두고 좌우 터치 버튼 사이에 배치한다. 겹칠 경우 보급 문구를 짧게 줄이며 버튼의 입력 영역을 덮지 않는다.
- 세로 화면에서도 기존 16:9 플레이 영역과 조작을 유지한다. 자동 회전 강제·세로 전용 게임 규칙·다른 피격점을 만들지 않는다. 작은 세로 화면의 최종 가독성은 실제 렌더링으로 판단한다.
- 타이틀·일시정지·결과 패널도 같은 게임 영역을 기준으로 한다. 결과에 추가할 정보는 L08을 따르며 버튼 밖 잘림을 확인한다.

### 주무기·드론 표시

| 실제 상태 | HUD 표시 원칙 |
|---|---|
| 기본 무기 | 기존 기본 무기 아이콘·이름과 BASE Lv.N. 시간 대신 레벨과 MAX 여부 |
| 특수 무기 | 해당 이름·아이콘·남은 시간. 기본 성장 레벨은 짧은 보조 표기로 남김 |
| 특수 종료 직전 | 기존 3초 경고를 유지. 0초 이후에는 기본 상태로 전환 |
| 특수 연장 | 실제 적용된 잔여 시간과 상한을 표시. 게이지 분모는 L06의 시간 상한으로 통일 |
| 드론 | 주무기와 독립된 기존 슬롯·남은 시간·게이지 |
| 기본 레벨 상승 | 숫자 변경과 기존 획득 강조를 재사용. 항상 강화 얼굴·강화 음악을 유지하는 조건으로 만들지 않음 |
| 피격·저체력 | 실제 HP와 파일럿 상태를 전달. 주무기 이름·보급 종류를 경고 문구로 덮어쓰지 않음 |

특수 게이지가 기존 '최초 획득 시간 대비'에서 '최대 보유 시간 대비'로 바뀌는 것은 연장 시스템에 필요한 제안이다. 예고·획득 표시와 실제 발사 무기 정보는 같은 상태에서 계산한다.

### 상하 보급 예고 — 헬멧 바이저 HUD

사용자 첨부 이미지의 **위아래를 감싸는 얇은 곡선·중앙의 방향 표식·서로 다른 발광색**을 참고한다. 요청은 이미지의 정확한 복제가 아니라 헬멧에 투사된 HUD가 상공/하층을 알려 주는 느낌이다. [저장소의 참고 이미지](references/visor-hud-reference.png)는 2026-09-08 첨부 `codex-clipboard-b0f0fcfb-ca64-4efb-be71-6f770cb1a2fc.png`의 동일한 사본이며 상단은 노랑, 하단은 초록이다. 다른 환경에서는 이 상대 경로를 사용한다. 아래 구체적인 색·곡률·배치는 구현 제안이다.

- L07의 예고 시점에 게임 화면 위쪽과 아래쪽의 주변 시야를 넓게 감싸는 타원형 호를 표시한다. 위쪽은 위로 볼록하고 아래쪽은 아래로 볼록한 형태로 바이저의 곡면감을 만든다. 중앙 전투 공간은 투명하게 유지한다.
- 호의 중앙에 상단은 작은 위쪽 표식, 하단은 아래쪽 표식을 둔다. 실제 보급의 고도 방향을 알리는 화면 고정 HUD이며 기체의 이동·롤·카메라 변화와 함께 흔들리는 월드 오브젝트로 만들지 않는다.
- 위쪽 노랑/앰버, 아래쪽 초록/민트를 첫 비교색으로 제안한다. **색은 상하 방향에 고정**하고 무기 변경/유지의 무작위 배치가 바뀌어도 서로 바꾸지 않는다. 아이템 종류는 별도의 아이콘·문구로 전달한다.
- 선은 얇은 중심선과 절제된 후광으로 표현한다. 예고 시작에 짧게 밝아진 뒤 읽을 수 있는 강도로 유지하는 안이다. 첨부의 불투명한 청색 바탕은 게임을 덮는 패널로 사용하지 않는다.
- 종류·남은 시간은 각 호의 방향 표식 가까이에 작은 라벨로 연결한다. 기존의 독립적인 상하 텍스트 행 제안은 이 곡면 HUD 안의 라벨로 대체한다. 예시: `↑ LANCE · 3.0s`, `↓ EXTEND +15s · 3.0s`. 기본 상태라면 `BASE Lv.2 → 3`처럼 현재 효과를 보여 준다.
- 수치는 L06·L07의 상태에서 읽는다. 변경 무기의 이름·아이콘 노출은 R03을 따르며, 미공개 선택이면 CHANGE를 사용한다. 방향색이 결과 무기를 뜻하는 색으로 변하지 않게 한다.
- 등장 전에는 등장까지 남은 시간, 등장 후에는 획득 가능 시간을 표시한다. 먹거나 만료된 쪽의 호·표식·라벨만 종료하고 반대쪽은 유지한다. 보급 일정이 없는 동안 두 호를 항상 강하게 켜 두지 않는다.
- 주무기 만료·변경·기본 MAX 도달로 유지 효과가 달라지면 해당 라벨을 갱신한다. 변경 후보와 상하 배치는 다시 추첨하지 않는다.
- 크기 기준은 검은 여백을 제외한 실제 게임 영상 사각형이다. 파일럿·중앙 상태 패널·보스 게이지·터치 버튼과 겹치는 구간은 호를 끊거나 라벨 위치를 조절하는 방식으로 맞춘다. 좁은 화면에서도 방향 표식·아이템·시간을 남긴다.
- 텐션의 노랑 탄, 적탄, 보급의 실제 획득 표식과는 화면 위치·호의 형태·방향 아이콘으로 구분한다. 낮의 흰 구름과 밤의 발광 위에서 선과 글자의 대비를 확인한다.
- 전투 안내 우선순위는 피해/HP·무기 정보 → 보급 정보 → 보스 진입 → 구간/격파 문구다. 보스 진입과 보급이 겹쳐도 양쪽 보급의 방향·종류·시간은 남긴다.
- HUD는 입력을 가로채지 않는다. 동작 축소 시 등장 밝기 변화를 줄여도 방향과 초읽기는 유지한다. 배경의 속도 변화·음악 박자를 HUD의 보급 시간 기준으로 사용하지 않는다.

## 3. 낮·밤과 속도 연출 제안 — P02

사용자가 확정한 방향은 D22다. 아래 배율 기준·색·전환 시간은 구체적인 검토안이다. '2배 이상'은 **보스 직전 일반전 속도의 2배**로 해석한 추천안이며 최종 검토에서 확정한다.

### 스크롤 곡선

| 시점 | 최초 일반전 속도 대비 배율 | 표현 |
|---|---:|---|
| 일반전 0초 | 1.00× | 완전히 맑고 밝은 푸른 하늘 |
| 15초 | 1.10× | 낮을 유지하며 완만하게 가속 |
| 30초 | 1.25× | 스크롤의 상승이 체감되는 구간 |
| 42~45초 | 1.50× | 일반전의 최고 속도, 보스 예고 |
| 보스 진입 후 | 3.00× | 직전 1.50×의 2배, 최초 속도의 3배 |
| 보스 격파 후 | 1.00× | 새 일반전 시작부에서 낮과 기본 속도로 복귀 |

- 일반전의 각 기준점을 부드럽게 연결하고 42~45초는 1.50×를 유지한다.
- 보스 진입 시작부터 0.8초 동안 밤과 3.00×로 전환한다. 전투 시작 전에 전환을 마쳐 첫 공격을 읽게 한다.
- 격파 직후부터 1.0초 동안 낮·1.00×로 돌아간다. 다음 45초는 격파 즉시 시작하므로 복귀 연출 때문에 대기 시간을 덧붙이지 않는다.
- 현재 배경 기준 속도 값 1.3을 1.00×로 취급하는 구현안을 제안한다. 절대 속도 값과 배율을 중복 적용하지 않는다.
- 배경 이동·추진 잔상·관련 환경 표현에만 적용한다. 플레이어 이동, 적탄, 적 행동, 보급 이동, 무기·보급·구간 타이머는 각 전투 사양을 따른다.
- `sceneTime`, 배경 누적 거리, 구름 연결 위치를 전환 때 0으로 되돌리지 않는다. 역주행·순간 점프·같은 구름 반복으로 속도를 표현하지 않는다.

### 밝기와 색

| 요소 | 맑은 낮 추천 | 보스 밤 추천 | 보존할 점 |
|---|---|---|---|
| 높은 하늘 | 청명한 파랑 #228EFF | 짙은 남색 #030B20 | 어두운 청록 안개가 화면 전체를 덮지 않음 |
| 수평선·산란 | 밝고 투명한 하늘색 #B8E8FF | 푸른 밤빛 #0E2345 | 고도별 원근과 하늘/지상의 구분 |
| 구름 | 햇빛을 받은 흰색, 푸른 그림자 | 외곽이 읽히는 차가운 달빛 톤 | 기존 밀도·깊이·앞뒤 관계 |
| 숲·지형 | 녹색 재질과 밝은 대기 | 어두운 녹청색, 실루엣과 원근 유지 | 지형 형상·종류·이동 경로 |
| 기체·적·탄 | 원래 재질색·위험 중심이 잘 보임 | 핵·탄·예고가 우선 식별됨 | 실제 판정과 발광 외곽의 구분 |

색은 방향을 설명하는 화면 제안이며 기존 소스의 확인값이 아니다. 새 태양·달 그림이나 별 자산을 필수로 추가하지 않는다. 낮/밤의 변화는 배경 광원·대기·구름·지형에 함께 적용하고 화면 위 검은 덮개 하나로 끝내지 않는다.

현재 볼륨 구름은 밀도와 조명을 사전 계산하는 부분이 있다. 보스마다 3D 텍스처를 다시 굽는 방식은 피하고, 기존 밀도/형상을 재사용하면서 조명색·밝기를 실행 중 전달하는 방식을 우선 제안한다. 필요한 셰이더 변경은 현재 구조 안에서 최소로 한다. 구름 샘플 수·해상도·후처리를 기본적으로 늘리지 않는다.

낮과 밤 모두 상공·중앙 구름·하층의 역할이 보여야 한다. 보급 방향을 찾기 위해 구름의 깊이감을 제거하거나 고도 이동을 단순 화면 이동으로 바꾸지 않는다.

## 4. 조작과 카메라 — P03

- 기존 키보드·마우스·터치의 최대 속도, 이동 범위, 카메라 추적, SV-01 회전 및 발사 위치를 우선 유지한다. 상하 보급을 쉽게 만들기 위해 한 입력만 더 빠르게 이동시키지 않는다.
- 포인터 입력은 실제 게임 영상 사각형에서 1280×720 좌표로 변환한다. 전체 화면·세로 여백·창 크기 변경 뒤에도 같은 규칙이다.
- 터치 이동과 SHOT의 동시 입력을 유지한다. 포인터 취소·캡처 해제·일시정지·탭 이탈·재도전에서 눌림과 이동 상태를 정리한다.
- UI 버튼을 눌렀을 때 배경의 발사·게임 시작 입력이 함께 들어가지 않게 한다. 일시정지 안의 음소거/전체 화면은 게임을 재개하지 않는다.
- 상하 보급은 L07의 비행 좌표에서 생성한다. 기존 화면/월드/카메라 회전 변환을 재사용하고 HUD의 화살표 좌표를 충돌 좌표로 쓰지 않는다.
- 양쪽 보급의 도달성이 부족하면 승인된 조정 범위에서 L07을 조정한다. 기체 핵·획득 반경·입력 속도를 몰래 확대하지 않는다.

## 5. 빛·소리·전투 효과·파일럿 — P04

최신 방향은 **루미네스의 빛·소리·행동 반응을 슈팅에 적용하는 것**이다. 구체적인 사건별 표현, 음악 직접 연계 제외, 현재 구조의 가능성과 충돌은 [빛·소리·전투 연출](AUDIO_VISUAL.md)에서 한 번만 관리한다.

### 개정하는 범위

- 기존 발사·탄·명중·격파를 무기별로 연결된 빛과 전자음의 표현으로 다듬는다. 효과 수와 음량만 증가시키는 것을 목표로 삼지 않는다.
- 기존 '현재 폭발·샘플을 재사용하며 소규모 연결만 한다'는 초안은 최신 방향에 맞게 수정한다. 원본은 보존하고 새 파티클 형태·시간 곡선·발광·발사/명중 음색의 개정안을 검토한다.
- R14는 사건 중심의 즉시 반응으로 확정됐다. 음악의 BPM·박자·조성에 직접 연계하는 구현은 제외한다.
- 총알의 외곽 빛과 피해 판정의 핵을 구분한다. 정확한 발사 간격·궤적·피해·예고·점수는 레벨 설계를 따른다.
- 작은 핵을 유지하며 L09 텐션의 시작·갱신·발사·적 명중·만료를 같은 전투 사건으로 표현한다. 강화 탄은 발사 시 저장한 피해/색/명중 큐를 유지하는 제안이다. 무기/드론의 기존 강화와 별도 상태이며 BGM 전환을 텐션 보상에 자동 연결하지 않는다.
- 새 효과음은 레시피 생성·기술 분석·비교 재생 도구에 실제 음원을 입력받는 오디오 평가 모델을 연결하는 안을 검토한다. D32에 따른 조사·실증 계획은 SFX_WORKBENCH, 모델 연결·자격·자동 채택 범위는 R17에서 관리한다. 사용자의 최초 후보 선택을 필수화하지 않는다. BGM 변경은 혼합에 실제 필요할 때 R15에서 결정한다.

### 계속 보존할 파일럿·기체의 연결

SV-01의 발사 위치·21프레임·기수 회전, 파일럿 FX3의 프레임·마스크·피격 우선순위·내부 반동 의도를 우선 유지한다. 기본 레벨만 오른 상태를 영구 강화 얼굴의 조건으로 삼지 않는다. 특수 무기 또는 드론이 활성화된 기존 강화 상태는 계속 사용한다.

작은 HUD에서 반동이 과해지지 않도록 기준 크기에 대한 비율로 내부 이동량을 축소하는 안은 유지한다. 루미네스 참조를 이유로 기존 기체나 파일럿 그림을 교체했다고 가정하지 않는다.

### 음악 배정의 현재 검토 상태

기존 6곡은 사용할 수 있는 배경 음악 후보 자산이다. 새 효과음과의 혼합 적합성을 청음하기 전에는 그대로 사용해 원하는 감각이 난다고 결론 내리지 않는다. BPM·조성 분석은 이번 구현의 필요 작업에서 제외한다.

초안 1은 title → ending → boss → danger → powerup → normal의 상황 우선순위를 제안했다. 현재 소스는 danger가 boss보다 우선이다. **이 우선순위 개정도 아직 미승인**이며 R11·R15에서 상태 전달과 실제 혼합을 기준으로 결정한다. 음악 교체를 전투 사건의 효과음·파티클 시간 기준으로 사용하지 않는다.

파일럿의 저체력 기준 25%와 현재 음악의 HP 30 기준은 서로 다르다. 이를 같은 기존 기준이었다고 쓰지 않는다. 곡의 재생 속도를 화면 스크롤에 맞춰 가속하는 것도 자동 승인하지 않는다.

### 제작·검증 연결

새 효과음이 필요하면 원본/편집본·출처·용도·실행 경로를 구분한다. 기존 발사음 변주·명중 재질·정지/음소거·종료 처리와 충돌하는 부분을 함께 검토한다. 현재 구조와 후보 제작 방식은 AUDIO_VISUAL에 있으며 아직 자산은 제작하지 않는다.

합의된 시각·오디오 검토와 V33~V41·V47~V49를 P04의 합격 기준에 추가한다. 신호·샘플 로딩 검사만으로 음악성·관전의 즐거움·혼합 음질이 검증됐다고 보고하지 않는다.

## 6. 메카닉·사운드 자산 제작 — P05

적·보스의 제작 방식은 **Blender 모델링과 애니메이션 렌더 스프라이트**로 정해졌다. 기존 곤충형 외형을 유지하거나 이미지 생성으로 신규 적을 만드는 제안은 대체한다.

상세 디자인·모델·가동부·약점·카메라·프레임·원본/실행본 규칙은 [메카닉 제작](MECHA_ART.md), 효과음의 레시피·제작 화면·자동 분석·비교·채택 절차는 [효과음 제작 도구](SFX_WORKBENCH.md)에서 관리한다.

- 사각 회전 드론 → 중간급 메카닉 → 보스가 공통 장갑·프레임·에너지 부품의 디자인 계열로 읽히게 한다.
- 현재 SV-01과 파일럿을 기준으로 삼는다. 기존 플레이어와 파일럿을 이번 요청으로 다시 제작하지 않는다.
- 적/보스의 구체 종수·고유 모델/파생형·인간형 여부·변형·프레임 예산은 R04·R19에서 확정한다.
- 약점 노출·개폐·포구 전개·반동을 실제 전투 상태와 연결한다. 노출 상태의 피해 규칙은 R18에서 결정한다.
- 기존 곤충 아트·제작 원본은 보존하지만 새 완성본의 임시 대체 자산으로 채택하지 않는다.
- Blender에 열려 있는 다른 작업의 장면을 덮어쓰지 않는다. 새 파일/독립 프로세스에서 제작하고 원본·렌더·파생본·메타데이터를 함께 보존한다.
- 오디오 모델을 연결하는 자동 평가 경로는 조사했으나 실제 자율 개선에 성공한 것으로 기록하지 않는다. 평가기 검증·연결·자동 채택 기준 R17을 확정해야 품질 절차가 완성된다.
- 모든 제작 도구·모델·음원 구현은 문서 전체 승인 후 시작한다.

| package.json, tools/build-site.mjs | 새 모듈 구문 검사와 명시적 실행 파일 목록 연결 | 누락 없이 빌드하고 원본·문서·임시 QA를 실행 산출물에 넣지 않음 |

새 모듈 추가는 이 문서에서 제안하는 작은 책임 분리다. 게임 전체를 여러 관리자 클래스로 재구축하는 승인이 아니다.

### 상태·이벤트·초기화

- 일반전/보스 진입/보스 전투의 단계와 해당 경과 시간, 격파 수, 다음 보급 일정, 기본 레벨, 고정된 보급 후보를 게임 상태가 소유한다.
- 텐션 시간·탄별 근접 인정 여부·발사 시 피해/표현 정보도 게임 상태가 소유한다. L09의 실제 피해 우선 처리와 일시정지·재도전 초기화를 적용한다. 기존 `powered`·특수/드론 만료·파일럿 우선순위와 혼합하지 않는다.
- 기본 조준은 예고 시작의 `attackAngle` 고정에서 실제 발사 시 플레이어 핵 방향 계산으로 바꾸는 설계다. 조준선은 발사까지의 움직임을 표시하고, 탄 발사 뒤에는 직선으로 유지한다.
- 연속 고리·탄 줄의 전체 시퀀스 동안 공격원을 예약한다. 묶음마다 예약을 해제하지 않으며 여러 포구·호위·HP 단계 전환도 같은 예산을 공유한다. 42초 이후 새 일반 예고를 막고 진행 중 시퀀스의 45초 정리를 적용한다.
- 전투 시간은 조작 가능한 시작 이후의 게임 시간이다. 구간 시간과 별개이며 일시정지에서 둘 다 멈춘다. 보스전 길이는 실제 진입 시작부터 격파까지 기록한다.
- 화면의 초읽기·예고는 게임의 다음 이벤트를 읽는다. UI가 이벤트를 소비하거나 후보를 다시 생성하지 않는다.
- 보급의 양쪽 생성은 하나의 이벤트로 원자적으로 처리한다. 각 개체의 획득/만료는 독립적이다.
- 생존 시간·구간·격파 수·레벨·보급 후보·무기·적탄·파일럿 이벤트는 재도전 규칙에 맞춰 초기화한다. 배경 거리의 연속성과 게임 기록 초기화를 혼동하지 않는다.
- 새로운 시드/최고 점수 정책은 L08의 승인 결과에 따른다. 기존 저장값 삭제·네트워크 저장은 포함하지 않는다.
- 새 모듈과 신규 자산을 동적 참조로 추가했다면 직접 개발 서버와 dist 양쪽에서 요청·디코딩·실제 표시를 확인한다.

## 8. 승인 후 한 번의 실행 순서 — P07

한 번의 실행은 승인된 전체 작업을 같은 요청 안에서 끝까지 진행한다는 뜻이다. 단계별 별도 승인을 계속 요구하지 않으며, 새로 생긴 중요한 미결 선택과 결과물의 지정 검토는 질문한다.

**다음 표는 전체 완성본의 순서다.** 1차 확인본만 구현하라는 지시를 받으면 [FIRST_IMPLEMENTATION 6절](FIRST_IMPLEMENTATION.md)의 순서로 I01~I07을 완료한다. 아래 2단계의 새 Blender/오디오 평가기 준비 때문에 1차 전투 구현을 막지 않는다.

| 순서 | 작업 | 다음 단계로 가기 위한 확인 |
|---:|---|---|
| 1 | 전체 승인·최종 역할/규칙·제작 범위 확인, 현재 소스와 비교 화면 확보 | 문서 기준, 사용자 변경, 원본 위치, 미결 해소 |
| 2 | 공통 메카닉 기준과 대표 모델/가동부, 효과음 제작 도구·오디오 평가기 실증과 대표 음색 준비 | 합의한 시각 검토와 평가기 자격/자동 채택 기준 확인. 제작 기준 확정 후 대량 파생 |
| 3 | L01·L02·L06~L09의 구간·난도·성장·보급·텐션·보상·기록과 최소 HUD 구현 | 전환·초기화·근접/피해 경계·발사 시 피해·양쪽 이동 검사 |
| 4 | L03~L05·L10의 편대·메카닉 역할·3속도 조준·4패턴·R18 약점 연결 | 전체 시퀀스 예산·발사 예고·몸통/핵·노출·시간에 따른 생존 경로 |
| 5 | 채택된 적/보스 모델·기믹 렌더와 효과음 변주를 제작·연결 | 프레임/피벗·발사구·약점·로딩·원본/실행본·소리의 채택 상태 |
| 6 | P01~P04의 UI·낮밤/속도·파티클·사건별 소리를 통합 | 정상/강화/저체력/보스/터치 화면, 단발/연사/전투 혼합 |
| 7 | 결함 수정 후 전체 테스트·구문 검사·빌드와 실제 실행 | QUALITY 필수 시나리오, 메모리·부하·청음/시각 한계 기록 |
| 8 | 현재 인계·변경 목록·검증·자산 상태 갱신, 인앱 검토 결과 제시 | 구현·검증·사용자 승인·게시 상태를 구분해 보고 |

의존 순서를 지키되 같은 기능의 상태와 최소 화면 연결은 함께 확인한다. 신규 아트 승인 때문에 대기하는 동안 기존 패턴·UI·검증처럼 독립적인 승인 범위를 계속 진행한다.

과거 QA ZIP 재작성, 긴 전체 플레이 영상, 새 프로젝트·태스크·예약 자동화 생성은 이 실행의 기본 단계가 아니다.
