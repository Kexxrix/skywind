# SkyWind 전체 개선 — 검증과 합격 기준

문서판: **검토 초안 7 / 2026-09-08 KST / 문서 게시·타 환경 인계 / 게임 구현 미시작**.

이 문서는 승인 후 구현을 무엇으로 통과시킬지 정하는 검증 제안서다. 아래 시나리오는 미래 계획이며 지금 통과했다는 보고가 아니다. 전투 수치는 [레벨 설계](LEVEL_DESIGN.md)와 [탄막·텐션업](BARRAGE_DESIGN.md), 화면·코드·제작 범위는 [전체 개선 설계](IMPLEMENTATION.md), 사용자 결정과 승인 상태는 [결정 기록](DECISIONS.md)을 따른다.

## 2. 문서 초안과 구현용 확정본

초안 완료 조건:

1. 사용자 확정 답변 D01~D41과 설계의 의미가 일치한다. D09의 대체된 초기 해석, D27이 제외한 음악 직접 연계, D30·D31이 대체한 곤충 외형·이미지 생성 제작안을 최종 완성본의 사양으로 사용하지 않는다. D32의 자율 평가 조사, D33~D38의 전투 방향, D39의 첫 확인 범위, D40의 상하 바이저 HUD, D41의 Git 게시·다른 환경 인계를 반영한다.
2. 포함 범위마다 구체 추천안·관련 소스·예외·합격 조건이 있다.
3. 현재 구현과 앞으로 만들 사양을 구분한다. 진행·무기·보급·전체 예산 L01~L08은 LEVEL_DESIGN, 근접/텐션·개별 탄막 L09~L10은 BARRAGE_DESIGN에서 관리하며 같은 값을 서로 다르게 정의하지 않는다.
4. 검토 항목 R01~R21의 상태가 일치한다. R14는 D27로 해소됐으며 나머지 미결 제안을 확정 결정으로 기록하지 않는다.
5. 대체하는 과거 규칙과 보존할 규칙이 명확하며, 역사적 증거를 현재 명령으로 취급하지 않는다.
6. 한국어 문서의 로컬 링크·요구사항 ID·소스 참조가 유효하다. 코드 식별자는 원래 이름을 유지한다.
7. 완성한 초안을 인앱 문서 패널에 열어 사용자가 검토할 수 있다.
8. 다른 환경의 첫 구현 시작 안내와 HUD 참고 이미지가 Git에 포함되고, 문서 링크가 기존 PC의 임시 경로에 의존하지 않는다. 문서 게시 성공은 원격 브랜치의 커밋으로 확인하며 게임 구현·새 환경 실행·공개 배포와 구분한다.

**구현용 확정본**은 승인받을 범위의 중요한 선택·시험 기준·검증·완료 조건이 일관되어야 한다. 전체 완성본은 전체 승인, 한정 확인본은 구체적인 해당 범위의 구현 지시를 기록한 뒤 진행한다. 초안 작성이나 일부 질문의 답변은 전체 승인이 아니다.

**첫 확인본의 검사 범위는 [FIRST_IMPLEMENTATION 8절](FIRST_IMPLEMENTATION.md)이다.** I01~I07과 첫/두 번째 난도에 해당하는 V 검사를 적용하고 새 메카닉·제작 도구·자율 오디오 평가·극한 V57은 후속 미수행으로 남긴다. 기존 자산의 정상 로딩/표시와 기존 오디오 회귀는 여전히 검사한다. 첫 확인본이 통과해도 전체 57개 검증의 완료로 확대하지 않는다.

## 3. 실행할 검사와 범위

현재 프로젝트는 외부 npm 의존성 없이 Node 기본 테스트를 쓴다. PowerShell 실행 정책상 필요한 경우 `npm.cmd`를 사용할 수 있다.

| 변경 종류 | 필요한 검사 |
|---|---|
| 문서만 변경 | 문서 간 대조·링크·경로·식별자, git diff --check, 변경 파일 범위 |
| 전투 규칙·상태 변경 | 관련 Node 테스트, 의미 있는 새 경계 검사, npm run check, 실제 관련 플레이 |
| HUD·입력·렌더링 | 관련 상태 검사, 실제 브라우저 화면·입력·겹침·크기 비교 |
| 오디오 | 이벤트·동시 재생·정지/해제 검사와 실제 혼합 청음의 확인 가능한 범위 |
| 실행 모듈·자산 목록 | 로딩·디코딩·해시/참조, npm run build:site, 산출물 실제 실행 |
| 전체 개선 통합 | npm test, npm run check, npm run build:site와 아래 필수 시나리오 |

같은 소스와 조건에서 통과한 검사를 이유 없이 반복·확대하지 않는다. 새 변경·실패·남은 우려가 생겼을 때 관련 검사와 필요한 통합 검사만 다시 한다. 문서 수정마다 게임 테스트·빌드·영상 검사를 돌리지 않는다.

기존 100개는 조사 기준 시점의 테스트 수다. 새 규칙에 맞게 시간 기반 난도·옛 보스 일정·순환 무기 등의 기대값을 바꾸되, 통과만 얻기 위해 판정을 약화하거나 무관한 검사를 없애지 않는다.

## 12. 증거와 최종 판정

- 기본 증거는 자동 검사 결과, 실제 스크린샷, 짧은 플레이/관측 기록이다.
- 화면 크기·입력·일반 플레이/통제 상태·소스 기준을 증거와 함께 적는다. 과거 화면·측정·배포 기록을 새 결과로 재사용하지 않는다.
- 움직임을 기록해야 하는 구체 필요가 있을 때만 5~10초 장면을 사용한다. 녹화·인코딩이 정체하면 무한 재시도하지 않고 대체 관측과 한계를 기록한다.
- 최종 보고는 요구사항 L01~L10·P01~P07에 대해 구현, 관련 V 검사, 실제 관측, 사용자 시각/청음 검토, 남은 항목을 연결한다.
- 기술적 통과는 사용자의 취향 승인이 아니다. 새 메카닉·낮밤·UI·최종 혼합 중 사용자 검토가 필요한 범위는 R12·R13·R17의 확정 결과를 따른다.
- 필수 미달은 수정하거나 정확한 장애를 밝힌다. 기준을 낮추거나 미완료 항목을 문서에서 삭제해 전체 완료로 만들지 않는다.
- 소스 구현·검증·사용자 승인·GitHub 게시·Sites 공개 배포는 별도 상태다. 이번 초안은 어느 것도 새로 완료했다는 의미가 아니다.
