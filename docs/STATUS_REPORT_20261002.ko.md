# SkyWind 프로젝트 현황 보고서

작성 목적: 집 PC의 현재 프로젝트가 무엇을 구현했고, 실행 가능한지, 다음에 무엇을 확인해야 하는지 판단하기 위한 읽기 전용 진단이다.

**현재 로컬은 실행 가능한 1차 전투 확인본이다.** 기존 자동 테스트 164개, JavaScript 구문 검사, 정적 빌드가 모두 통과했고, 실제 Chrome에서 개발본과 빌드본의 화면·게임 시작을 확인했다. 전체 설계의 완성이나 최종 플레이 감각·청음 승인을 뜻하지 않는다.

가장 먼저 알아야 할 차이는 **로컬이 GitHub보다 문서 커밋 2개 뒤처져 있다는 점**이다. 원격에서는 현재 상태의 진입 문서를 `STATE.md`로 정리했지만 이 PC에는 아직 없다. 해당 두 커밋에는 게임 코드 변경이 없다. 동기화와 코드 수정은 수행하지 않았다.

## 2. 프로젝트 목적과 대상

SkyWind는 숲 위 저공비행과 구름 사이의 상승·하강을 배경으로 한 **무한 진행 웹 횡스크롤 슈팅 게임**이다. 일반전과 보스전의 긴장·해소, 상하 보급 선택, 작은 피격 핵 주변의 근접 회피 보상, 빛·소리의 즉각적인 반응을 중심으로 한다. 기체와 파일럿은 건담 00 오마주 방향, 전투 시청각은 사건에 반응하는 연출 방향이다. 음악 박자에 맞춰 전투를 지연시키는 설계는 제외되어 있다.

대상 이용자에 대한 별도 사업·시장 문서는 확인되지 않았다. **조작 지원과 게임 구조로 보면 PC 브라우저의 키보드·마우스 이용자와 모바일·태블릿 터치 이용자를 겨냥한 게임으로 해석할 수 있다.** 이는 기능에 근거한 추론이며, 검증된 시장 타깃이나 모든 기기 지원 보증은 아니다.

근거: [README](../README.md) 3·50–64행, [결정 기록](plan/DECISIONS.md) 36–65행, [1차 구현 범위](plan/FIRST_IMPLEMENTATION.md) 109–118행.

## 8. 다음 작업 권고

1. **작업 기준 문서부터 맞춘다.** 원격 문서2커밋과 `STATE.md`를 검토한다. 허용된 후속 동기화 작업에서는 사용자 변경을 보존하고 실제 HEAD를 다시 확인한다. 게임 기능을 처음부터 다시 만드는 단계는 아니다.
2. **R6의 첫 두 사이클을 사람 입력과 청음으로 검토한다.** 한쪽/양쪽 보급·늦은 출발·보스 진입·격파·정지·게임오버/재도전을 확인하고, 보스 처치 시간과 불편 지점을 기록한다. 현재164개 자동 테스트는 이 검토의 기반으로 활용한다.
3. **대표 모바일 실기에서 HUD와 터치를 확인한다.** 특히 세로 화면, 보급/특수/저체력/보스 HUD가 겹치는 순간, 동시 이동·사격과 정지 메뉴를 본다. 게임이 작동한다는 기존 피드백과 새 버전의 읽기·조작 문제를 구분한다.
4. **현재 사양과 역사 문구를 정리한다.** 최신 속도·접근 흡수·1차 승인 상태를 분야 문서의 현재 규칙과 연결한다. 이전 QA·스크린샷·원본 해시는 그대로 보존한다.
5. **그 결과를 바탕으로 다음 제작 범위를 확정한다.** 후반 난도, 메카닉·약점/장갑, 효과음 제작·평가기는 필요한 선택·자산·예산을 갖춘 별도 작업이다. 탄수/효과/자산을 늘리기 전에 고밀도·반복 플레이 성능과 원본 백업을 확인한다.
