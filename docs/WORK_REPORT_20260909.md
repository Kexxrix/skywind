## 2. 상하 아이템 문제의 원인과 최종 수정

중앙 회복은 보이는 즉시 근접 흡수가 가능했지만 상하 보급에는 예고 종료 전 흡수 금지가 남아 있었다. 시드71의 정상 입력에서 하단 보급을78.57 거리로 스친 뒤 상승하면, 예고 종료 시 이미 범위를 벗어나 보급을 놓쳤다. 계속 하강해48 거리로 붙어도 예고가 끝날 때까지 반응하지 않았다.

또한 R5의0.10초 감속 곡선과 거리12 조기 획득이 결합되어 가까운 아이템은 약0.033초 만에 사라졌다. R6에서는 다음을 적용했다.

- 실제 접근 중인 보급도 회복과 같은 흡수 조건을 사용한다. 기존 공급 시계·종류 선정·경로·만료 시각은 유지하지만 경로상 근접하면 기준 도착 시각보다 일찍 획득할 수 있다.
- 전방·상하212와 후방318을 유지한다. 피해 핵1.85는 별도이며 흡수 범위 변경의 영향을 받지 않는다.
- 이동할 거리가 있는 아이템은 최소0.14초, 최대0.18초 동안 기체의 현재 위치로 이동한다. 이미 중심12 안에서 접촉한 경우는 즉시 획득한다.
- 아이콘은 이동의65%까지 원래 크기를 유지하고 마지막에 줄어든다. 실제 이동 경로 뒤로 최대120 길이의 빛 꼬리를 그린다.
- 범위 안에서 잡힌 아이템은 만료 시각을 넘어도 흡수를 마치며 효과는 한 번만 적용한다. 만료된 아이템은 새 흡수를 시작하지 못한다.

이전 R4/R5 수치와 ‘예고 종료 전 획득 금지’ 기록은 당시 상태다. 현재 동작에는 R6가 우선한다.

## 5. 다른 환경에서 이어가기

새 폴더에서는 다음과 같이 시작한다.

```sh
git clone https://github.com/Kexxrix/skywind.git
cd skywind
git log -1 --oneline
npm test
npm run check
npm start
```

기존 체크아웃은 먼저 `git status --short --branch`를 확인한다. 미커밋 변경을 보존하고, 깨끗하며 원격보다 단순히 뒤처졌을 때만 `git pull --ff-only`로 갱신한다. 파일럿 HUD만 들어 있던 과거 공개본이나 R1의 검증용 지문으로 최신 소스를 덮어쓰지 않는다.

현재 외부 npm 실행 의존성이 없어 `npm install`은 필요 없다. Node.js와 WebGL 2/하드웨어 가속 브라우저가 필요하며, 로컬 기본 주소는 `http://127.0.0.1:5173/`다. PowerShell 실행 정책 문제는 `npm.cmd`로 실행할 수 있다. 과거 PC의 Temp·Blender·Python·FFmpeg·외부 오디오 API 키는 실행에 필요하지 않다.

읽기 순서는 [AGENTS.md](../AGENTS.md) → [HANDOFF.md](../HANDOFF.md) → 이 보고서 → [다른 환경 안내](../FIRST_IMPLEMENTATION_HANDOFF.md)와 관련 소스다. I01~I07을 다시 만드는 대신 이미 구현된 기능과 사용자의 다음 요청을 대조한다. `npm run build:site`는 빌드 생성이며 공개 배포가 아니다.

## 6. 보존 범위·남은 작업

- 기체 크기·SV-01 회전/WebP·파일럿 초상/FX3·피해 핵1.85·기존 자산 원본·음악 곡·사운드 권한 기록·Sites 연결은 보존했다. 새 의존성·엔진·Blender 자산은 추가하지 않았다.
- 이번 기준본은 첫/두 번째 시험 난도를 반복한다. 세 번째 이후 최종 난도, 새 메카닉/약점/장갑·지역·무기 콘텐츠, 효과음 제작 앱/자율 청음 평가기는 미구현이다.
- 전체 믹스의 직접 청음·최종 음질 승인, R6의 장시간 수동 플레이/모바일 실기 정량 성능·최종 밸런스는 남아 있다. R1의 보스 구간18.70/28.92초는 약15초 목표와 차이가 있었으며 이후 체감 검토가 필요하다.
- GitHub 게시와 Sites 배포는 분리한다. 기존 공개 게임의 마지막 배포 기록은 버전5이며, 이번 R1~R6의 공개 사이트 반영은 별도 지시 후 수행한다.
